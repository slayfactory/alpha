**Журнал заявок `breakout tick --keep-orders`** (TK-743, В-193; по умолчанию выключен, `trades.csv` и деньги те же байт в байт). Рядом со сделками — два файла на сторону:

- `<side>-orders.csv` — все заявки входа и выхода, одна строка = одно событие заявки: `sym,level,sig_ms,lot,oid,role,type,event,ms,px_e8,size_u,share_pm,aux_ms,note`. Заявка = `(sym, level, sig_ms, lot, oid)`; `lot` 0 — лот 1, 1 — лот 2 (`e2`); `role`: `e1` вход (рыночная заявка в момент сигнала → исполнена в момент входа, лимитная у мейкера), `e2` второй вход (условная заявка на `уровень − d`: place в момент входа лота 1, fill / cancel с причиной в `note`, `aux_ms` — момент срабатывания условия), `take1…takeN` лестница тейков (лимитки; `reprice` при пересчёте `tj`), `stop` (стоп-заявка: place на входе, `reprice` — безубыток / трейл / NATR-стоп / остаток после тейков, одно событие на мс; fill — выход стопом, `note` = вид: `stop` / `be` / `trail`), правила выхода от уровня `nx` / `tu` (до касания), `rt` / `tx` (после касания; `aux_ms` — срок), `trail_limit` (лимитный трейл `tl`), `exit` (рыночный выход при конце данных). `type`: `limit` / `market` / `stop` / `cond`; `event`: `place` / `reprice` / `fill` / `cancel`; `px_e8` — настоящая цена ×1e8 (0 — цены нет, правило по времени); `size_u` — мкУЕ (500 000 000 = ставка 500 $), `share_pm` — тысячные ставки. Заявки, не исполненные к выходу, снимаются в момент выхода (`cancel`, `note` = причина). Строки сделки идут в порядке `trades.csv`, внутри — по времени события.
- `<side>-setup.csv` — уровни сетапа каждой сделки: `sym,level,sig_ms,role,px_e8,from_ms,to_ms,reason` (`to_ms` пусто — жив). Роли: `level` торгуемый уровень (рождение — `from_ms`, конец — `to_ms` и причина в `reason`: `aged` / `pk` / `close_above`), `ver` версии его цены (активная на сигнале — `active`), `zone_near` цена версии, `zone_entry` нижний край зоны входа (`dmax_e8`), `zone_far` дальний край `P_far`, `touch` члены активной версии (пивоты-касания: бар, цена), `touch_gone` выпавшие члены, `next` следующий уровень (цель тейка `tn`), `other` прочие живые уровни монеты на минуте сигнала с состоянием в `reason`: `live` / `pk@мс` / `pb@мс` / `ban@мс` (запрет с минуты) / `consumed@мс` (уже торговался). Данные — из `Level` движка (журнал членов, версии цены, причина конца) и из прохода состояний `candidates_group_tr`; время — мс от 01.09 00:00 UTC.
- Прогон V0nt: `bash tools/p42/tk743_run.sh <бинарь> <md5>` (юнит на srv, `MemoryMax=40G`), гейт «сделки байт в байт» — `tools/p42/tk743_gate.sh`, счёт заявок по ролям — `tools/p42/tk743_counts.py`; файлы — `/data/p42-tk743/trades/<прогон>/<окно>/<cid>-{trades,orders,setup}.csv`.
**Ключи движка пробоев TK-747** (В-194, В-195, В-196, В-197; по умолчанию выкл. — сделки побайтно прежние; только `breakout tick`, в `breakout run` отвергаются). Строка варианта `ключ=значение`:

- `lm=1` — уровни без средних («уходим от среднего», В-194; «не дальний, ближний», В-197): цена уровня — ближний к цене пивот сетапа (шорт — самый высокий из минимумов, лонг — самый низкий из максимумов; `0` — среднее, как раньше); допуск `tau` группы (рождение уровня, присоединение пивота) мерится от цены этого пивота, не от среднего. Прочие члены лежат дальше по ходу пробоя и остаются со своей ценой (`--keep-orders`: роль `touch` — все члены, роль `inner` — внутренние уровни каскада с числом проколов и наибольшим заходом). Убийцы «закрытие за ценой» и `pk` считаются с бара пивота, давшего цену. Только `lx = 0`.
- `lz=1` — закол (В-194, В-196, В-197: «если сетап 2 пивота и допускающий уровень, то отмена; если каскад — нормально»): сетап ровно из двух пивотов, где второй — допускающий (новый) пивот — позже первого и дальше него по ходу пробоя (шорт — ниже минимум; строго — цены биржи кратны шагу), не рождается; пивоты остаются свободными, с третьим дают каскад (≥ 3 пивота) — он не отменяется. Только при `n_bounce = 2`, `lx = 0`.
- `pp=1` — любой минутный прокол (В-197, заменяет `pk` и `pb`; несовместим с `pk`): после постановки версии цены уровень убит (запрещён со следующей минуты), как только минута зашла за цену уровня дальше допуска — 1 шаг цены, если шаг ≤ 0,05 % цены, иначе 0 (шаг монеты — наибольший общий делитель цен минуток, `Sym::tick`); закрытие часового бара за ценой дальше допуска убивает уровень и при построении. Основной уровень — цена версии (`lm = 1` — ближний пивот); внутренние уровни каскада (прочие члены) колоться могут, из каскада выходят только закрытием часового бара за ними. В `--keep-orders`: роль `main_pierce` (заходы основного уровня в пределах допуска с версии цены до сигнала: минут и наибольший заход ×1e8), роль `inner` (то же для каждого внутреннего уровня), причина прокола `pp@мс` у прочих уровней.
- `fw=<минуты>` — свежесть по владельцу вместо (а) / (б) §13.14: вход на минуте `t` — только если (1) с постановки уровня (подтверждение последнего присоединившегося пивота версии цены) прошло ≥ `fw` минут; (2) проторговка в закрытых минутах `[max(постановка, t − fk), t)`: ≥ `fm` % закрытий строго ниже уровня и не дальше `fb` от него, ни одного закрытия на уровне или за ним; (3) после постановки было касание — минута с high не ниже `уровень − tau`. Требует `fm > 0`, `fh = 0`, `fw ≤ fk`. Уровни источника (`lx ≠ 0`) допущены всегда. Постановка — подтверждение последнего присоединившегося (нового) пивота: старые уровни живут в окне `l` суток, но без нового пивота, «заметившего» их, сетапа нет (В-197); ключа «срока после старых уровней» (`fz`) нет. Пример: `fw=30 fm=50 fk=120 fb=0.5`.

**Очередь и установка бинарей на srv (TK-614, аудит TK-612 §1.3/§4).** (1) Очередь раннера: приоритет `RBUILD_PRIO` — 0 бинарь критического пути (`build-srv.sh build`), 1 ворота и проверки (`test`, `vps-check.sh` кроме `all`/`gate`), 2 `all`/`gate`; внутри приоритета — по приходу запроса; замок берёт только голова очереди (файлы `/opt/rbuild/queue/<приоритет>-<нс прихода>-<id>`). Раннеры старой версии берут замок напрямую, мимо очереди. Сборка идёт в scope `rbuild-<id>`; `id` — первая строка вывода (`rbuild: id=… prio=…`); `ssh srv bash /opt/rbuild/cancel.sh <id>` снимает запрос из очереди (клиенту rc 73) или останавливает только его scope (rc 73, результат не сохраняется, `install` не выполняется; чужие юниты не трогаются). (2) Установка по содержимому (`tools/rbuild-install.sh`, `rb_install`): `build-srv.sh <BIN_OUT> build` и `vps-check.sh bin` кладут файл в `<BIN_OUT>.<md5, 8 знаков>` (прежние не затираются, md5 печатается) и атомарно переставляют ссылку `<BIN_OUT>` (для `bin` — `<BIN_OUT>-plain`, `<BIN_OUT>-r2`); время изменения ссылки = время прихода поставившего её запроса: запрос, пришедший раньше, не затирает ссылку, поставленную более новым (печатает «новее запроса», файл `<BIN_OUT>.<md5>` остаётся). Прежний обычный файл на месте `<BIN_OUT>` сохраняется как `<BIN_OUT>.<его md5>`. Потребителю — звать `<BIN_OUT>.<md5>` (не ссылку) и сверять md5 перед стартом. Проверка: `docs/findings/rbuild-queue-md5-2026-11-19.md`.

## Флаги окружения `ALPHA_*`

- `lob bounce-grid` пишет снимок всех `ALPHA_*` процесса в `manifest.txt` (`env_count=<n>` и строки `env:ALPHA_X=значение`) — по ним видно, чем посчитан выход. Семантика «включён» у флагов разная (`=="1"`, `=="0"`, просто задан): `ALPHA_DIAG=0` включает.
- `ALPHA_E2E=<файл.jsonl>` — сквозной учёт времени монето-суток (TK-052, `bounce_grid/e2e.rs`): строка на стадию; без переменной ничего не делается. Боевой режим измерений, не тестовый стенд.
- Кэш `.abin` подходов и касаний (КТ-5, `touches/bincache.rs`): включён, когда задан `ALPHA_APPROACH_BIN_DIR` (зеркало пути CSV под ним); флагов `ALPHA_APPROACH_BIN`/`ALPHA_TOUCH_BIN` нет. `ALPHA_APPROACH_BIN_LEVEL` — уровень zstd обоих кэшей (`ALPHA_TOUCH_BIN_LEVEL` снят).
- Сайдкары счёта событий `<бинлог>.events` / `.carry-events` пишутся через tmp+`rename`, штамп файла — размер + mtime в нс (как у `.abin`); строка без перевода строки — промах и пересчёт.
- `ALPHA_COMMIT=<хеш>` на этапе сборки (`binrel`) — версия бинаря (`alpha --version`, `process.version` в health), иначе `unknown`. `ALPHA_REJECT_REASONS=1` (`=list` — ещё строка на каждое отвергнутое касание) — диагностика отказов фильтра касаний в `bounce-grid`, на счёт не влияет. `ALPHA_TLS_EXTRA_ROOT=<ca.pem>` — корень локального TLS-источника для `alpha collect stamperr`.

## Грабли

- `lob probe` и `lob latency` ставят реальные ордера; Bybit даёт `403` с части стран (CloudFront), с ПК и srv доступ есть.
- `instruments.csv` в корне записи = уже отобранный пул (пишет `lob pick`; читают `lob session`, `touches`, `record`), не список всех кандидатов; глубина ниже `DEPTH_FLOOR_USD_E9` никого не отсеивает (В-35) — колонка `depth_check`.
- Бинлог сессии ищется одним резолвером `commands::lob::session_binlog_for(dir, symbol)`: `<SYMBOL>-<дата>.binlog`; недатированный `<SYMBOL>.binlog` отвергается с подсказкой переименовать.
- В бинлоге две версии: **v3** пишет этот код (тело кадра = группы, группа = одно сообщение биржи); **v2** — форма живого коллектора до перезапуска, читается тем же `Reader`. Версия — байт в заголовке; все команды читают обе без флагов, `binlog-stats --reencode` считает только по v2. Запись ради формата не перезапускать — раскатка v3 на живой процесс решение владельца.
- Живой корень читается мягко: обрезанный хвостовой кадр не ошибка (`binlog::Reader::read_frame_soft`, `parts::read_frame_soft`, команда печатает «хвостовой кадр обрезан — файл дописывается»); строгий `read_frame` — там, где пишется артефакт (`binlog-stats --rewrite-out`).
- Сверка CSV после `csv.writer` — колонка может нести `
` (Python пишет строки с `
`; `cut -f1-N` на «последней» колонке сравнивает с `
` на конце): сравнивать после `tr -d '
'` с обеих сторон.
- Тест переподключения `conn.rs` детерминирован (`RecordingBackoff`), реального времени не ждёт; бэкофф — за приватным трейтом `Backoff`.
- Windows: Python на ПК — `PYTHONUTF8=1` (иначе китайские имена контрактов портятся); ssh с ПК — всегда с `-i` и `-o UserKnownHostsFile=…` (кириллица в HOME).
