# Критик: «окно от точки смены режима» для П-42 — хорошая ли идея (26.11.2026)

Роль — критик, только чтение, без счёта. Материал: рисунок владельца, `docs/plan/coord-handoff.md`, TK-692 (`kb/task/TK-692.md`, `docs/findings/p42-walk-forward-2026-11-24.md`, L-436, L-437), В-170, В-182, В-183, В-186.

**Поправка к брифу:** TK-692 посчитан (январь–июнь, шаги месяц / неделя / 3 сут., вердикт L-436, поправка L-437). Но окно там везде **накопленное с 01.01** — меняется частота переотбора, не длина окна. Скользящие окна фиксированной длины (14 / 30 / 60 сут.) не считались ни разу.

## 1. Прав ли владелец

- Да, по форме: у любого победителя бэктеста P&L сосредоточен во времени. Наши числа: шорт TK-692 — 94 % Σ за май–июнь (+1638 из +1741 $), один июнь — 67 %; февраль–апрель выбранное ≈ якорь (+103 против +86 $).
- Но это **не отличает** две причины:
  - **смена режима** — клетка правда работает в одном периоде и не работает в другом;
  - **шум отбора** — из 361 509 клеток максимум Σ даёт та, у которой удачная полоса длиннее; сосредоточенность во времени — признак любой удачи.
- Что следует: при смене режима переподбор на свежем окне помогает; при шуме — вредит (короче окно → больше шума в победителе).
- Как различить на наших данных: **устойчивость рангов клеток во времени** (корреляция Спирмена между Σ клеток в окне и в следующем периоде, по лагам 1…8 недель):
  - ≈ 0 на всех лагах — шум, переподбор бесполезен;
  - > 0 и ровно на всех лагах — стационарно, нужно самое длинное окно;
  - > 0 на лаге 1 и затухает — режим; время полураспада = допустимая длина окна + задержка детектора.
- Ещё одно: **общий режим или режим линии.** После мая выросли все шорт-линии (замороженные L384/L401: ≈ 4–5 $/сут. до мая, ≈ 8,6 $/сут. после). Если режим общий (рынок), лечится фильтром «торговать / не торговать», а не переподбором настроек.

## 2. Детектор точки смены + переподбор — сильные и слабые места

Что уже говорят данные (против коротких окон):
- Замороженные линии, подобранные на июле–ноябре (другое и длинное окно), на январе–июне заработали **ровнее** переподбора: до мая +359 / +440 $ против +103 $ у переподбора по месяцу.
- Чаще переподбор — не лучше: шорт 3 сут. +1679 $ против месяца +1741 $; лонг 3 сут. +30 $ против месяца +134 $.
- Лонг: ни один шаг не отличается от случайного → устойчивости рангов на месяц нет, детектору нечего ловить.

Ожидаемые провалы:
1. **Максимум шума на коротком окне.** 14 сут. × 361 тыс. клеток → победитель почти наверняка шум (у одной линии 30–65 сделок в месяц, за 14 сут. — 15–30). Окно от точки смены часто будет минимальным.
2. **Задержка детектора.** CUSUM / байесовский детектор по суточному P&L одной линии замечает падение через 2–4 недели. При режиме ≈ 1–2 месяца (май–июнь) задержка + 14 сут. минимального окна съедают бо́льшую часть режима.
3. **Лишние степени свободы:** тип детектора, порог, минимум окна, по какому ряду детектировать, пул. Каждый вариант — испытание; 2 × 3 × 2 = 12 на сторону ещё до выбора клетки.
4. **Ряд для детектора не определён.** P&L торгуемой линии меняет состав после каждого переподбора — точка смены будет отражать наши же переключения. Детектировать нужно по фиксированному ряду (пул / якорь / замороженная линия) — ещё одна настройка.
5. **Пул заглядывает вперёд.** Пул A отобран по Σ > 1 $ на 01.07–13.11 (В-183): январь–июнь — не чистая проверка, июнь соседствует с июлем → ранги в июне искусственно «устойчивы» (788465 / 728374). Любой тест на этом пуле завышает устойчивость; читать как верхнюю границу.
6. **Мало данных.** 181 сутки, по неделям ≈ 24 шага вне выборки, май–июнь держатся на 1–2 клетках. Подобрать детектор и проверить его на тех же 6 месяцах — подгонка.

## 3. Что дешевле и сильнее (по порядку, без движка)

1. **Т1 — устойчивость рангов** (п. 1): корреляция рангов по лагам 1–8 недель, отдельно для шорта и лонга, отдельно февраль–апрель и май–июнь; ноль — перестановка суток блоками.
2. **Т2 — кривая длины окна:** скользящее окно фиксированной длины L ∈ {7, 14, 30, 60} сут. + накопленное (уже есть, L-436); правило выбора PS-1007 §3, шаг неделя, E = 1. Детектор имеет смысл, только если какая-то L ≤ 30 лучше накопленного окна.
3. **Т3 — фильтр по кривой капитала** вместо переподбора: замороженная линия (L384, L401, якорь) торгуется, только если её P&L за последние N сут. > 0, N ∈ {7, 14, 30}. Мало испытаний; проверяет «режим общий → торговать / не торговать».
4. Детектор смены — только если Т1 показывает затухание, а Т2 — выигрыш короткого окна; сравнивать с **лучшим фиксированным окном**, а не с накопленным.

## 4. Вердикт: идти с изменениями

Не строить детектор сейчас. Первый шаг — Т1 + Т2 (+ Т3 справочно), без движка.

- **Данные:** `mass_day` TK-700 (`/data/p42-tk700/mass/mass.sqlite`, только чтение), пул A `all1`, шорт и лонг, сутки 0–180 (01.01–30.06). Пересчёта нет (В-213): ряды есть. Июля–ноября по пулу в `mass_day` нет (≈ 61 ЦП-ч), не нужен. Справочно июль–ноябрь — суточные ряды клеток веера c539 (TK-674, В-186: только для этого).
- **Запуск:** в окне HOLD на границе пакета, не рядом с идущим счётом.
- **Испытания:** Т2 — 4 длины × 2 стороны = 8, Холм по 8; Т1 — описательно; Т3 — 3 × 3 линии, справочно.
- **Правило (записать в протокол до счёта):** детектор переходит в протокол, только если
  - (а) в Т1 у шорта корреляция на лаге 1 > 0 и нижняя граница блочного бутстрепа > 0 в **обеих** половинах (февраль–апрель и май–июнь);
