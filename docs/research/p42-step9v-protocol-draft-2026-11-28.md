**Вопрос.** Есть ли у корзины похожих монет край, который держится на другой корзине тех же свойств **в те же месяцы** сильнее, чем на случайных монетах и случайных сделках тех же суток; в какие сутки он есть; узнаётся ли такой режим на других периодах?

**Порядок (владельца, не меняется).** (1) корзины по свойствам монеты, измеренным до сделки — §13.79.1; (2) внутри корзины фильтры ужесточаются, пол — 10 сделок — §13.79.2; (3) проверка на двойнике в те же месяцы — §13.79.3; (4) описание режима по данным на момент входа — §13.79.4, только после (3); (5) перенос на другие периоды — §13.79.5. Деления по времени на этапе поиска нет; **подгонку под время судит только перенос (шаг 10), не двойник** — двойник торгует в те же сутки через тот же рынок и подгонку под сутки / часы не видит (критик, п. 1).

**Метки чисел:** *измерено* (источник), *модель* (допущение названо), *оценка* (моя прикидка), *назначено* (решение протокола; критик вправе оспорить). Модель, оценка и «назначено» решений не двигают.

#### Общие правила

1. **Режимы — по правилу, не использующему P&L линий (критик, п. 3):** режим 1 = **FJ** (01.02–30.06, 150 суток UTC), режим 2 = **SEL** (01.07–13.11, 136 суток UTC) — границы заданы раньше этого протокола геометрией данных (деревья TK-695 / TK-686 и окна m02–m06 для FJ; окна wa / wb / wc для SEL; план §3 п. 3). **Поиск — внутри каждого режима отдельно, двойник — в тех же месяцах того же режима.** Месяцы по исходу S1 не выбираются. «Один режим» здесь — операционное определение (календарный блок); является ли он одним рыночным режимом, описывает §13.79.4. Январь и N1 в поиске не участвуют (§13.79.5).
2. **База 9в — якорь s4 / члены B (критик, п. 6), не S1; это вариант V0 шага 7 (L-519 п. 3: список шага 7 — V0 и V2′; V2′ в 9в не входит, судится в шаге 7).** База = **уникальные сделки** 9 клеток B шорта (`tk726_cell`: 7180015…7180023; якорь s4 = `BS-l7-tf60` = 7180023) без точных повторов (функция дедупликации TK-727, L-477: 67,5 % строк семейства — повторы). S1 / S2 / L401 в 9в не берутся (отобраны на SEL, 2,1 млн клеток). Лонг не входит (сделок лонга за SEL на диске нет — план §1.7).
3. **Единица — сутки UTC** (день входа, `entry_day`/`entry_ms`, как в `tools/p42/tk726_exits.py`). Монеты ходят вместе через рынок: статистик по отдельным сделкам как независимым наблюдениям нет, t-статистики по сделкам нет. 4. **Одна главная мера (критик, п. 2):** **средний `net` $ на сделку отобранных сделок на двойниках, сведённый по всем корзинам типов режима, относительно нуля «случайное подмножество того же размера из той же корзины в те же сутки»** (формулы — §13.79.3). Все остальные меры (доля плюсовых суток, R:R, убыток на стоп, σ суточного $, Шарп, просадка, перехай) — описательные, решений не двигают; они печатаются по В-169.

**Ворота свойств G-prop (без сделок):** (1) устойчивость — ранговая корреляция Спирмена значений в двух непересекающихся окнах ≥ **0,5** (назначено): P1–P3 — окна «30 суток до формирования» и «предыдущие 30 суток»; P4 — чёт / нечёт сутки с поправкой Спирмена–Брауна. **Типы (корзины по свойствам).** k-means на рангах годных свойств, **K = 4**, зерно 20261127, k-means++, 100 перезапусков, минимум инерции; тип < 60 монет → K понижается (3, затем 2). Центроиды и таблица `t734_basket` — в БД до чтения P&L. Типы нумеруются по P1 центроида; в отчёт — слова («высокий V, крупный шаг…»). Сделка → тип по монете `sym`; монеты без типа (нет свечей, P4 при n = 0 → p₀ допустимо) в отчёте поштучно.

**Случайные деления на «корзину» и «двойник» (критик, п. 1).** Для каждого (режим, тип): **S = 100 делений монет типа пополам** (назначено, ≥ 100): перестановка монет, зерно сплита s = 20261127 + s (s = 1…100), первая половина — «корзина» B_s, вторая — «двойник» W_s; нечётная монета отбрасывается. Двойник «с теми же свойствами» по построению (две случайные половины однородного типа); баланс свойств B_s / W_s печатается (стандартизованная разность, KS), решений не двигает.

**Контрольные «случайные монеты» (нуль Б):** для каждого сплита s — случайный набор монет c539 **того же размера, что W_s, не по свойствам** (любой тип, без монет B_s), зерно 20262127 + s. Набор нужен для проверки «правило работает на этих монетах, а не на любых монетах те же сутки» (§13.79.3).

**Процедура (записана целиком; запускается на каждом сплите s, в каждом типе, для обеих настроек):**
1. R₀ = пусто (все сделки B_s).
2. Шаг j = 1…3: для каждого ещё не использованного признака и каждого значения порога считается правило R_{j−1} ∧ условие; допустимо, если оставляет **n ≥ 10 сделок за ≥ 5 разных суток** (пол, настройка L10), либо (настройка L40) **не менее 40 % сделок B_s**. Мера выбора **J = m − SE**: m — средний `net` $ на сделку, SE — ошибка m блочным бутстрепом по суткам (блок ⌈n_суток^{1/3}⌉, 2 000 повторов, зерно 20261127). Выбирается кандидат с наибольшим J.
3. Условие принимается, если J вырос по сравнению с J(R_{j−1}); иначе остановка. После j = 3 — остановка. Результат — правило R_s (или «правила нет», если не принято ни одно).
4. Настройки: **L10** — пол владельца (≥ 10 сделок), **L40** — удерживать ≥ 40 % сделок (единственная настройка, при которой пул отобранных сделок вообще может дойти до n_min; назначено). Обе в счётчике; решения по каждой отдельно.
5. Печатается: порядок шагов, число оценок, n и сутки отобранных сделок; **J, Σ, m на стороне поиска «найдено на этих данных» и решений не двигают**.

**Что реплицируется на двойнике.** Не «лучший признак», а **процедура** — повторённая на каждом из 100 сплитов; правило R_s, выбранное на B_s, оценивается на W_s и на случайных монетах — монетах, которых процедура не видела.

### 13.79.3 Шаг 9в-3. Проверка на двойнике: сплиты монет, нули, PBO, мощность, правило решения — ЧЕРНОВИК 28.11.2026 v2

**Слова владельца: «месяцы брать те же, но форвард-тесты делать на разных баскетах с одинаковыми характеристиками / режимами».** Проверка — правило R_s, найденное на B_s, на двойнике W_s **тех же типа и суток**. Деления по времени нет. **Двойник судит подгонку под монеты, не под время** (общий для обеих сторон рынок, сутки, линия и состав c539 в нём не отделены); подгонку под время судит только перенос (§13.79.5).

**Обозначения (на сплит s, тип t, режим):** n_s, m_s — число и средний `net` $ на сделку у сделок W_s, попавших под R_s; пул по типам режима: n_s = Σ_t n_{t,s}, m_s = Σ$ / Σn (отношение сумм). Правило «нет» → сплит-тип в пул не входит (число — в отчёт).

**Нули (критик, п. 1–2):**
- **Нуль А — случайные сделки той же корзины в те же сутки:** на каждом сплите 1 000 раз берётся случайное подмножество сделок W_s **того же размера**, с тем же числом сделок на каждые сутки (где суток не хватает — берётся всё, что есть); m_s^A — среднее по 1 000 повторов. Зерно 20263127 + s.
- **Нуль Б — то же правило, случайные монеты без подбора по свойствам, те же сутки:** правило R_s (абсолютные пороги, Φ) применяется к сделкам базы случайного набора монет (§13.79.1); m_s^Б — средний $ на сделку у попавших сделок.

**Первичная мера и тест (одна на режим × настройку).** M = (1/S)·Σ_s m_s — средний по сплитам пулированный $ на сделку на двойниках; **Δ_A = (1/S)·Σ_s (m_s − m_s^A)** — основная мера: общий для суток рыночный фактор вычитается нулём А. Интервал Δ_A и M — блочный бутстреп по суткам режима (блоки ⌈n^{1/3}⌉ и 21 сутки, 20 000 повторов): на каждом повторе сутки ресэмплятся целиком, правила R_s фиксированы, пересчитываются все m_s, m_s^A. Односторонний тест H0: Δ_A ≤ 0. **Холм 4** (2 режима × 2 настройки).

**PBO по сплитам монет (критик, п. 1):** для каждого сплита — ранг m_s правила R_s среди 22 однокондиционных правил Φ (те же пороги), посчитанных на W_s тех же суток; PBO = доля сплитов, где R_s в нижней половине ранга. Порог ≤ **0,2** (как PBO шага 8 плана; назначено).

**Печатается (критик, п. 1в):** корреляция суточных рядов `net` Σ $ отобранных сделок «корзина B_s — двойник W_s — случайные монеты» (по парам, среднее и разброс по сплитам); корреляция рядов **всех** сделок тех же трёх наборов; доля суток с обеими сторонами. Если корреляция «корзина — случайные монеты» ≈ корреляции «корзина — двойник» — двойник ничего не добавляет к «случайным монетам» (запись в отчёт).

**Правило решения (до счёта; для каждого режима и настройки отдельно; оба блока бутстрепа):**

*«Край корзины держится на двойнике»* — все условия:
- (i) **нижняя граница 95 % Δ_A > 0 после Холма 4** (оба блока);
- (ii) **PBO ≤ 0,2**;
- (iii) нуль Б: средняя по сплитам m_s − m_s^Б > 0 и нижняя граница 95 % > 0 (иначе исход «сутки, а не корзина: правило работает и на случайных монетах»);
- (iv) **мощность:** пул n̄ = (1/S)Σ_s n_s ≥ n_min (§13.79 п. 6) — иначе «не ясно (мощность)»;
- (v) не держится на одних-двух сутках или одной монете: доля двух лучших суток в Σ$ отобранных ≤ 50 %; без лучшей монеты Δ_A остаётся > 0 (точка);
- (vi) в пул вошло ≥ 3 типов.

*«Не держится»:* верхняя граница 95 % Δ_A ≤ 0 (оба блока) при n̄ ≥ n_min **или** PBO > 0,5. Вывод: край корзины — подгонка под монеты (план §8).

*«Не ясно»:* всё остальное (мощность; знак границы разный при двух блоках; <3 типов).

«Края нет» — нормальный и самый частый честный вывод (навык alpha-research). Вывод одного режима на другой не переносится — это §13.79.5.

**Отчёт (В-169; по типам, пулу и обеим настройкам, против базы двойника):** n, Σ $, $ на сделку, Шарп, просадка $ и % маржи, перехай (самый длинный, средний, p90), R:R, убыток на стоп, доля плюсовых суток, σ суточного $ — для (а) всех сделок W_s, (б) отобранных, (в) остальных; M и Δ_A с интервалами; N поиска, DSR на полном N; таблица «режим × настройка → n̄, M, Δ_A, PBO, нуль Б»; частота выбора каждого правила по сплитам; всё — «найдено на этих данных». По месяцам режима — описательно, без вывода. Описательно (если есть данные, G-src): те же замороженные правила на монетах **h775 \ c539** (236 контрактов TradFi, В-175) — только если сделок базы за режим по ним ≥ 100.

**Исходы и дальше.** «Держится» → §13.79.4 для этого режима. «Не держится» → стоп 9в по режиму, запись «край корзины — подгонка под монеты», направление — владелец. «Не ясно» → стоп, причина, решение координатора и критика (больше сделок базы? — новый протокол, не правка этого).

### 13.79.5 Шаг 9в-5. Перенос (шаг 10 плана): между режимами, N1 + январь, форвард — ЧЕРНОВИК 28.11.2026 v2
