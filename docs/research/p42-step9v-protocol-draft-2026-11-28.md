**Процедура (записана целиком; запускается на каждом сплите s, в каждом типе, для обеих настроек):**
1. R₀ = пусто (все сделки B_s).
2. Шаг j = 1…3: для каждого ещё не использованного признака и каждого значения порога считается правило R_{j−1} ∧ условие; допустимо, если оставляет — настройка **LF:** **n ≥ N_FLOOR сделок за ≥ 5 разных суток**; настройка **L40:** **не менее 40 % сделок B_s**. Мера выбора **J = m − σ̂_t / √n** (критик, п. 6): m — средний r на сделку правила, n — число его сделок, σ̂_t — разброс r на сделку по **всей базе (режим, тип)**, зафиксированный до поиска (§13 п. 6). Выбирается кандидат с наибольшим J. J детерминирован, бутстрепа внутри поиска нет.
3. Условие принимается, если J вырос по сравнению с J(R_{j−1}); иначе остановка. После j = 3 — остановка. Результат — правило R_s (или «правила нет», если не принято ни одно).
4. **Три запуска на сплит (критик, п. 3):** (а) по всем суткам режима — правило R_s (проверка §13.79.3 (i), (ii), (v)); (б) по **чётным** суткам режима — правило R_s^{чёт}; (в) по **нечётным** суткам — R_s^{неч} (перекрёстный двойник, §13.79.3). Чётность — по номеру суток режима (первые сутки = 1). Пол в (б) и (в) — тот же (N_FLOOR / 40 % от сделок половины), «правила нет» → сплит-тип не входит в Δ_X, число в отчёт.
5. Печатается: порядок шагов, число оценок, n и сутки отобранных сделок; **J, Σ, m на стороне поиска «найдено на этих данных» и решений не двигают**.

**Замороженное правило R\* (критик, п. 4).** R\*_{t,режим,настройка} = **эта же процедура, один раз запущенная на всех монетах типа (B ∪ W) режима по всем суткам**, с той же настройкой; «набор» = условия **вместе с абсолютными порогами**. R\* — то, что замораживается (`freeze/tk734-frozen.json`, `sha256`) и идёт в §13.79.4–5; частота наборов по 100 сплитам — описательно (отчёту; «правило, выбранное в ≥ ⅓ сплитов» из v2 отменено: набор в ≥ ⅓ сплитов маловероятен, замораживалось бы не то, что проверял двойник). R\* **не оценивается** на двойнике (он в её выборке); его судит перенос.

**Что реплицируется на двойнике.** Не «лучший признак», а **процедура** — повторённая на каждом из 100 сплитов; правило R_s, выбранное на B_s, оценивается на W_s и на случайных монетах — монетах, которых процедура не видела.

### 13.79.3 Шаг 9в-3. Проверка на двойнике: сплиты монет, нули, разложение Δ_A + Δ_D, PBO (CSCV), перекрёстный двойник, правило решения — ЧЕРНОВИК 28.11.2026 v3

**Слова владельца: «месяцы брать те же, но форвард-тесты делать на разных баскетах с одинаковыми характеристиками / режимами».** Проверка — правило R_s, найденное на B_s, на двойнике W_s **тех же типа и суток**. Деления по времени нет. **Двойник судит подгонку под монеты, не под время** (общий для обеих сторон рынок, сутки, линия и состав c539 в нём не отделены); подгонку под время судит только перенос (§13.79.5), а общие для типа движения суток — перекрёстный двойник «чёт / нечёт» (ниже).

**Обозначения (на сплит s, тип t, режим, настройку):** S_{t,s} — сделки W_{t,s}, попавшие под R_s; n_{t,d}, r — число сделок на сутки d и результат сделки; m̄_{t,d}(W_s) — средний r **всех** сделок W_{t,s} за сутки d. Пул по типам: n_s = Σ_t |S_{t,s}|, **m_s = Σ r / n_s** (отношение сумм), **m^{все}_s** — средний r всех сделок W_s тех же типов. Сплит-тип с «правила нет» не входит ни в числитель, ни в m^{все}_s (число — в отчёт).

**Нули (критик, п. 2, 14):**
- **Нуль А — те же сделки того же размера в те же сутки — формулой, без перебора подмножеств:** **m^A_s = Σ_t Σ_d n_{t,d}^{отб} · m̄_{t,d}(W_s) / Σ_t Σ_d n_{t,d}^{отб}** (математическое ожидание случайного подмножества с тем же числом сделок на каждые сутки; точнее и дешевле 1 000 подмножеств).
- **Нуль Б — то же правило, случайные монеты вне B_s ∪ W_s, со своим нулём А внутри набора:** для сплита s и типа t правило R_{t,s} (абсолютные пороги) применяется к сделкам базы случайного набора C_{t,s} (§13.79.1); m^Б_s — средний r попавших сделок; **m^{Б,A}_s = Σ_d n_d^{Б,отб} · m̄_d(C_s) / Σ_d n_d^{Б,отб}** — нуль А по тем же формулам на этом наборе; **Δ_Б = (1/S)·Σ_s (m^Б_s − m^{Б,A}_s)**.

**Разложение (критик, п. 2).** **Δ_A = (1/S)·Σ_s (m_s − m^A_s)** — внутри суток, монеты (общий рыночный фактор суток вычтен нулём А); **Δ_D = (1/S)·Σ_s (m^A_s − m^{все}_s)** — вес суток (правило выбирает хорошие сутки); сумма: **M − m^{все} = Δ_A + Δ_D**, где M = (1/S)·Σ_s m_s. **Δ_D на тех же сутках не судится, только печатается** (правило выбиралось на B_s, где вклад суток общий с W_s: отбор почти гарантирует Δ_D > 0, критик Р1). Вклад суток судится на «чужих» сутках перекрёстного двойника: **Δ_{D,X}** (ниже) — он идёт в маршрутизацию, а Δ_D на цели — в перенос (§13.79.5). Это нужно, потому что гипотеза владельца «сезонный режим, как продажа кондиционеров» — это именно эффект суток; обрыв 9в на Δ_A ≈ 0 до переноса спрятал бы его.

**Первичная мера и тест (две на режим × настройку: Δ_A и Δ_{D,X}).** Δ_A и Δ_{D,X}, интервалы — блочный бутстреп по суткам режима (блоки ⌈n^{1/3}⌉ и 21 сутки, 20 000 повторов): на каждом повторе сутки ресэмплятся целиком, правила R_s фиксированы, пересчитываются все m_s, m^A_s, m^{все}_s, m^Б_s, m^{Б,A}_s. Односторонние тесты H0: Δ_A ≤ 0 и H0: Δ_{D,X} ≤ 0; границы — односторонние 95 %. **Холм 8** (2 режима × 2 настройки × 2 меры; пул по типам; Δ_{D,X} — в том же семействе, что (i)). **Вторично — по каждому типу** отдельно (то же правило решения, **Холм 32** = 2 режима × 2 настройки × 4 типа × 2 меры); исход «держится по типу t» засчитывается и идёт в §13.79.4–5 (критик, п. 7: пул из 4 типов размывает край одного типа вчетверо, а владелец предлагал «взять только удачные монеты»). Верхняя граница для «нет» берётся на уровне Бонферрони (α/8 для пула, α/32 для типов) — в ту же сторону строгости.

**PBO по CSCV-аналогу (критик, п. 5).** Для каждого сплита s ранг правила R_s считается **среди всех допустимых правил пространства процедуры** (≤ 1 047; допустимо = пол настройки выполнен на W_s) **по тому же критерию J**, что при выборе, на W_s тех же суток. **PBO = доля сплитов, где R_s в нижней половине ранга** (ранг ≤ медианы по J от лучшего, равные — средний ранг). Порог ≤ **0,2** (как PBO шага 8 плана; назначено). Деления — по монетам, не по времени.

**Перекрёстный двойник (критик, п. 3; «двойник в другие сутки тех же месяцев»).** Правило R_s^{чёт} (выбрано на B_s по **чётным** суткам режима, §13.79.2 п. 4) оценивается на W_s по **нечётным** суткам, правило R_s^{неч} — на W_s по **чётным**. **Δ_X = среднее по сплитам и по двум направлениям (m − m^A)** на «чужих» сутках (нуль А той же формулой на этих сутках). **Δ_{D,X}** (критик, Р1) — вклад суток на тех же «чужих» сутках: **(1/S)·Σ (m^A − m^{все})** правила R_s^{чёт} на нечётных сутках W_s и R_s^{неч} на чётных (m^A и m^{все} — формулы выше на этих сутках), среднее по двум направлениям и сплитам; если на половинах режима «правила нет» — Δ_{D,X} не определено: O4 не срабатывает, для O5 считается ≤ 0. Условие (vii): **Δ_X > 0 (точка) и Δ_X ≥ ½ Δ_A**; иначе исход получает пометку «сутки типа». Месяцы те же, поэтому слову В-190 («месяцы брать те же») не противоречит; общие для типа движения суток (например: в сутки, когда мемы падали, сильнее падали мемы с высоким V) в «чужие» сутки не переходят. Если координатор сочтёт иначе — печатается только описательно, но обязательно.

**Печатается (критик, п. 1в):** корреляция суточных рядов r Σ $ отобранных сделок «корзина B_s — двойник W_s — случайные монеты» (по парам, среднее и разброс по сплитам); корреляция рядов **всех** сделок тех же трёх наборов; доля суток с обеими сторонами. Если корреляция «корзина — случайные монеты» ≈ корреляции «корзина — двойник» — двойник ничего не добавляет к «случайным монетам» (запись в отчёт).

**Правило решения (до счёта; для каждого режима и настройки отдельно — пул и затем типы; оба блока бутстрепа; ворот мощности нет).**

Условия:
- (i) **нижняя граница 95 % Δ_A > 0 после Холма** (оба блока);
- (ii) **PBO ≤ 0,2**;
- (v) не держится на одних-двух сутках или одной монете: доля двух лучших суток в Σ$ отобранных ≤ 50 %; без лучшей монеты Δ_A остаётся > 0 (точка);
