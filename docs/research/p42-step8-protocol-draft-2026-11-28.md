### 13.81 Шаг 8. Совместный поиск: вопрос, база, пространство, что запрещено

**Вопрос.** Добавляет ли поиск **одной линии** (одна клетка движка, одно сочетание значений) к базе B\* то, что переживает процедуру выбора, повторённую целиком на обучающих сутках, — а не лучшая клетка перебора? Судится **процедура выбора** (PBO, вложенная проверка) и **разность «линия − база»** вне выборки, не лучший прогон: по плану §6 у шага 8 испытаний больше бюджета ≈ 2–3 независимых конфигураций (два года данных держат ≈ 7, у нас 328 суток, из них 286 в поиске), поэтому «лучшая клетка» судьёй быть не может.

**Главное ограничение (Д1; критик).** На 286 сутках построены база (якорь s4 выбран на SEL, L-334), семейство (из 2,1 млн клеток карты), оси (влияние шага 6 по Σ $ SEL), пороги `thr674.json` (найдены на SEL). Вложенная проверка повторяет только выбор шага 8, не выбор базы и пространства. Поэтому **абсолютный знак P&L на этих сутках — не доказательство** (он почти гарантирован при базе в плюсе). Решение: процедура, PBO, условие правила и далёкие области работают с **парной суточной разностью «точка − база»** Δ_p(t) = x_p(t) − x_B\*(t); абсолютные числа остаются описательными с меткой «база построена на этих сутках». Шаг 8 на этих сутках **не может доказать край**: его законный продукт — **один кандидат для чистой проверки** и ответ «добавляет ли поиск к базе»; «край найден» — только после шага 10.

**Что опровергнет.** PBO процедуры > 0,2, или плато (точно, движком) не держится, или нижняя граница парной разности ≤ 0 → «в этом семействе края нет» (O2, §13.81.3), база идёт дальше без поиска (ноль новых испытаний) — законный исход; направление решает владелец.

**База B\* = V0 (L-542, шаг 7: O2 «не помогло» по шорту B9 и лонгу s3; параметр установлен).** B\* — **одна линия: якорь s4** (клетка `BS-l7-tf60`, cid `7180023`): `bm=1 e=0.15 e2=0.05 ew=5 fh=4 fm=50 lat=4 latx=4 pb=1 pk=1 rf=0.2 rs=2 s=4 t24=12 tb=0.1 tt=20 l_days=7`, без `vf` (рабочего стопа нет; источник — §13.80, проверка — G-src). Ключи, которых нет в пространстве, заморожены на B\*. Равновесный ряд B9 (судья шага 7) — рядом, описательно. m_B\* — средний суточный $ якоря s4 за 286 суток (печатает G-src; P&L базы читал шаг 7).

**Сторона.** Только шорт; **лонг не ищется** (Q4: у лонга своего правила не было, влияние осей шага 6 — 0,152, измерено, L-507, прежний исход «не работает»; шаг 7 дал лонгу O2). Отдельная ветка — только если лонг получит O1, и своим протоколом.

**Окна и сутки.** FJ 01.02–30.06 (150 суток, окна m02…m06) + SEL 01.07–13.11 (136 суток, окна wa / wb / wc) = **286 суток** (измерено, план, сокращения). Состав — c539 (В-175). Все точки считаются на **всех восьми окнах**: обучение / тест делятся по суткам, не по окнам. **Чистый набор — только форвард с 25.11** (правило e-процесса плана, шаг 10); 2025 — только со словом владельца (план, шаг 10). ### 13.81.1 Шаг 8-1. План точек (закрыт до счёта), S по замеру цены

**Принцип.** Все точки считаются движком **точно** на восьми окнах (суточный ряд полным прогоном; срезы обучения / теста — позже, из готового ряда; повтор процедуры движка не требует). Суррогат (ридж по точным рядам, §13.81.2) только упорядочивает (V3). Кода выборки Соболя в репозитории нет — пишется (`tools/p42/step8_design.py`, тест на известные свойства: размерность, равномерность, воспроизводимость по зерну).

**1. Опорный набор R (V1).** Скремблированный (Оуэн) набор Соболя (`scipy.stats.qmc.Sobol(d=D, scramble=True, seed=<зерно варианта>)`), **S = 2^m точек** по всему пространству. Отображение u → значение оси:
- порядковые и непрерывные **обязательные** оси (`n_bounce`, `k`, u_lo): линейно по интервалу; целые — округление к ближайшему;
- категории — равные корзины по u (LS — 5, `nf` — 3, `F:sharp` — 2);
- **необязательные фильтры F1 (q_hi), `F:n60`, F3 (w) имеют долю «выкл.» (Д6): u ∈ [0,85; 1] → «выкл.» (доля 15 %, назначено), u ∈ [0; 0,85) → активное значение линейно по интервалу оси.** При «выкл.» связанные координаты (φ при w «выкл.») не действуют, дубли склеиваются по `cell_id`. Без этого точек с выключенным фильтром в R почти нет, база не выбирается и поверхность в её области экстраполирует;
- q_hi ограничен снизу u_lo + 0,15 (пересчёт интервала).
Недопустимые комбинации движка отбрасываются **до счёта** (проверка `Params::validate`, как `cell_ok` TK-674) и заменяются следующей точкой последовательности; список замен печатается. Эффективные дубли (разные точки с одинаковым действующим набором ключей, оси, не действующие при данном LS, и «выкл.») склеиваются по `cell_id`; N считается по уникальным и по сырым точкам.

**2. Точки по осям (OAT).** Для каждой координаты — все значения сетки при остальных на базе B\* (категории — все уровни; целые — все; непрерывные — 5 уровней в интервале по u, плюс «выкл.» для необязательных). Ожидаемо ≈ 30 точек (G-axes печатает точный список). Назначение: опорный ряд «ось за осью» (описательно) и кандидаты процедуры; **в PBO в опорный набор не входят**; база B\* — точка OAT с Δ ≡ 0.

**3. Далёкие области (п. 9(4)).** Четыре оси **вместе** вне базы: `e ∈ {0,05; 0,1; 0,15; 0,3; 0,5}`, `rf ∈ {0; 0,1; 0,2; 0,3}`, `tt ∈ {0; 5; 10; 20; 40; 60}`, `d ∈ {0,25; 0,5; 1; 2}` — **значения карты TK-674** (`tools/p42/tk674_axes.py:177-199`, измерено; решётка 5·4·6·4 = 480 точек, расчёт). Берётся **128 точек скремблированного Соболя в этой 4-мерной решётке** (зерно 20261127 + 2, значения — ближайшие узлы, дубли склеиваются; остальные ключи — на B\*; **назначено**, вместо 480: Холм по 480 бесполезен по мощности). Считаются движком, суточные ряды сохраняются. Блок **не входит** ни в R, ни в PBO, ни в выбор кандидата. Суд — §13.81.3 п. 7: **парно против B\*** (Q2).

**4. Коробка вокруг кандидата (V4).** Для замороженного кандидата c (функция c и δ, не истории поиска): **2d точек по осям** (d = число порядковых / непрерывных координат варианта; P10: 7 → 14 точек, ±δ) + **256 точек Соболя** в коробке ±δ (скремблированный Соболь, зерно 20261127 + 1, категории и состояния «выкл.» зафиксированы на значениях c). **δ (назначено):** ±1 шаг для целых (`n_bounce`, `k`), ±0,10 длины интервала u для u_lo, q_hi, `F:n60`, ±0,10 · 24 ч для φ и ±0,10 · 20 ч для w. Клетки коробки входят в N. Коробка считается **после** выбора c на полной выборке (один раз); для 45 вложенных разбиений коробки не считаются — соседей даёт поверхность (§13.81.2 шаг 5; отступление от «каждый шаг точно», названо, только в сторону усиления).

**5. S по замеру цены (правило записано до замера; Д7).**
- **Замер (В-213, без чтения P&L):** первые **8 точек** R (префикс последовательности — они же войдут в прогон) × **два окна: m04 и wb**; печатаются только время, число клеток-окон, число суток окна (**d_m04 и d_wb печатает G-axes**; SEL-окна ≈ 45 суток, m04 ≈ 30), клеток за проход и число сделок; суммы $ не читаются до полного прогона. Режим прогона = режим замера (то же число клеток за проход, тот же бинарь TK-706 m3, c539, дамп сделок).
- c_day = (t_m04 + t_wb) / (d_m04 + d_wb) — секунд на точку-сутки; **c_pt = c_day · 286 · 1,25** (секунды на точку по восьми окнам; множитель 1,25 — запас на разброс цены между фильтрами и малую выборку из 8 точек, **назначено**; 286 / 30 ≈ 9,5 эквивалентов m04).
- Ориентир (**измерено**, разные режимы счёта; клеток за проход разное): TK-718 — 931 с на ≈ 1 430 клеток-окон (0,65 с); TK-726 — 3 мин 20 с на ≈ 78 клеток-окон (2,56 с). Разброс ×4 — потому и замер.
- **Правило S:** S = наибольшее из {4 096; 2 048; 1 024; 512}, при котором **(S + ≈ 30 + 128 + 14 + 256)·c_pt ≤ T_max**, **T_max = 16 ч** машинного времени движка на srv (**назначено**; Q1: принять как потолок, не поднимать; один движок за раз). Если даже S = 512 не укладывается — исход **O6-цена** (шаг не считается; план просит ускорять метод, не просить хост: В-159, В-150). При S < 1 024 вероятен O6 по плотности (G-pow8). Замер — **после `lock`**, до G-pow8; S записывается записью `freeze` до G-pow8 и до первого полного прогона (Д4).
- Ориентир модели: при c_cw = 0,65 с (c_pt ≈ 0,65·8·1,25 = 6,5 с) S = 4 096 → ≈ 7,5 ч; при 2,56 с (c_pt ≈ 25,6 с) S = 2 048 → ≈ 16 ч — на границе (**модель**, не замер).

**6. Что хранится.** По каждой точке: ключи, `cell_id`, суточный ряд P&L ($, ставка 500 $, маржа 250 $) на 286 суток, сделки по суткам, число стопов и $ на стоп, число сделок — в БД на srv `/data/p42-step8/step8.sqlite` (**назначено**, В-179), таблицы `s8_point`, `s8_day`, `s8_trade_n`, `s8_split`, `s8_path`, `s8_pbo`, `s8_pow`, `s8_check`.

### 13.81.2 Шаг 8-2. Процедура выбора (записана целиком до счёта)

Процедура Π применяется **без изменений** (а) к обучающим сутками каждого из 45 разбиений вложенной проверки, (б) к полной выборке 286 суток для замораживаемого кандидата, (в) в синтетических мирах G-pow8. Вход — суточные ряды точек R ∪ OAT (без блока далёких областей и без коробки), множество обучающих суток T. Зерно любой случайности — **20261127**. **Цель процедуры — разность с базой (Д1):** для каждой точки p ряд Δ_p(t) = x_p(t) − x_B\*(t) на T; абсолютные ряды в процедуре участвуют только в допуске (шаг 1).

**2. Мощность до движка — парный G-pow8 (как G-pow §13.80.1; синтетика, движок не нужен; Д3).**
- **Модель мира (модель; допущения названы):** S синтетических точек **замороженного** S на тех же u-координатах; суточный ряд x_p(t) = μ(θ_p) + e_p(t), ряд базы x_B\*(t) = m_B\* + e_B\*(t) (база — точка с θ_B\*). **Шум e — одной линии:** гауссов процесс в пространстве координат (длина корреляции ℓ из G-cov) × сутки (блочно, блок 7: остатки суточных рядов **якоря** и клеток карты, **перемешивание суток** — сохраняет хвосты и автокорреляцию), σ — **одной клетки** (якорь 7180023 и клетки карты; ориентир σ ≈ 12–13 $/сутки по рядам семейства L-508, расчёт из Σ и Шарпа; **измерено**). B9 — **только для формы общего дневного фактора**, с перешкалированием на σ одной линии (дисперсия среднего 9 клеток ниже — мощность была бы завышена).
- **Три мира:** (н0) **μ ≡ 0**; (нB) **μ ≡ m_B\*** (все точки как база, края нет); (A) **μ(θ) = m_B\* + A · exp(−‖θ − θ\*‖² / 2w²)**, θ\* — случайная точка (зерно), **w = 2δ** (решает), печатаются также w = δ и w = 4δ. Мир (A) при **A = A_max = m_B\*** (удвоение базы линии; **назначено**, P&L базы прочитан шагом 7); сетка A для MDE: 0,25 / 0,5 / 1 / 1,5 / 2 × m_B\*.
- **Прогон:** в каждом из **R = 100 миров на тип** (н0, нB, A_max; 300 миров × 45 разбиений × Π; снижение R — только по правилу бюджета п. 4) процедура Π + вложенная проверка + правило **по C′ и PBO** (A, C′; B — по синтетической коробке: точки коробки генерируются той же моделью как новые синтетические точки) → доля O1.
- **Печатается:** (а) доля O1 в мирах н0 и нB (ложное срабатывание; **нужно ≤ 0,10 в обоих**, назначено); PBO в н0 и нB (должно быть ≈ 0,5, иначе ошибка кода); (б) **мощность при A = A_max** (**нужна ≥ 0,8**, назначено) и **MDE\_proc** — наименьшее A из сетки, при котором доля O1 ≥ 0,8; (в) то же для w = δ, 4δ; (г) минимальное A для флага DSR (планка п. 5 §13.81.3); (д) SE суточного среднего разности по модели (σ / √286).
- **Маршрут:** если мощность при A_max < 0,8 **или** ложные O1 > 0,10 в н0 или нB → **O6**: решающих прогонов нет (экономия ≈ 16 ч движка), в чистую проверку идёт B\* без поиска. Тот же G-pow8 печатает, что нужно и что возможно. G-pow8 не меняет S, диапазонов, процедуры и вариантов (без подгонки под симуляцию); единственный маршрут — идти или O6.
