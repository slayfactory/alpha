## Что лежит в БД

| таблица | строка | неизменяемость |
|---|---|---|
| `entry` | запись: время GMT+4, задача TK, проект П-NN / G-NNN, вид, гипотеза, вердикт (работает / не работает / не ясно / описательно), $ на ставку 500 $, сделок, Шарп, «найдено на этих данных», текст | всегда (триггеры): исправление — новая запись `--corrects L-N` |
| `protocol`, `psec` | протокол и его разделы (§): заголовок, номер, вид (правила / ворота / α / правило вердикта / данные…), α, «до счёта» и когда записан | раздел «до счёта» — неизменяем; поправка — новый раздел `--amends` |
| `metric` | число записи (TK-647): запись × сторона (long / short / both) × клетка × вселенная × окно — сделок, Σ $ на ставку 500 $, $ / сделку, Шарп (годовой по дневному), вердикт, «найдено на этих данных», «из текста», источник: файл в git + коммит + место (путь JSON / строка) | всегда (триггеры); повтор той же строки (`h`) не пишется; строки с `ckey` / `bin` — клетки бэктеста (TK-674), см. «Хранилище клеток» |
| `metric_gap` | почему у записи нет чисел (TK-661): запись × причина (предрегистрация / заморозка / не запускалось / числа не вписаны / чисел сделок нет), пояснение, где видно (файл + строка); на сайте — «нет чисел: …» в списке и в записи | всегда (триггеры); повтор (запись + причина) не пишется |
| `psec_flag`, `psec_num` | исправление флага «до счёта» / номера раздела (строка `psec` неизменяема); вид `psec_cur` читает последнее | только добавляются |
| `link` | типизированная ссылка src → dst: запись, раздел, протокол, задача, решение В / S, карточка kb, коммит, файл (заморозка, отчёт) | только добавляются |
| `file_move` | перенос файла / каталога в git «старый путь → новый» (TK-704, схема v9): строки `link` и `metric` неизменяемы и хранят прежний путь, `check` находит файл по новому | только добавляются |
| `kb_node` | карточки kb (решения, задачи, протоколы…) — связанный индекс; сами карточки — md в git (`kb/`) | заменяется `sync-kb` |
| `doc`, `chunk` | снимки перенесённых md: файл восстанавливается байт в байт (`export-md`) | — |

Узлы: `L-N` — запись, `PS-N` — раздел протокола, `P-42 §13.28` — раздел по номеру, `P-42-level-breakout` — протокол, `TK-646`, `G-022`, `В-167`, `S-225`, id карточки kb, коммит (SHA), путь файла. Ссылки видны в обе стороны: `chron.py links <узел>` и блоки «Ссылки» / «Обратные ссылки» на сайте.

## Команды (`python tools/chron.py …`)

С ПК и из любого worktree команда сама идёт на srv по ssh (`-i ~/.ssh/id_rsa`, `UserKnownHostsFile` — кириллица в HOME; переменные `CHRON_SSH_KEY`, `CHRON_KNOWN_HOSTS`, `CHRON_HOST`); на srv — `python3 /data/chron/chron.py …` прямо с БД. Коммиты и файлы в ссылках проверяются по git там, где запущена команда.

## Хранилище клеток бэктеста (TK-674, миграция 7, 22.11.2026)

Слова владельца 22.11: «Результаты в бд загоняем то что уже прогоняли не делаем» → «Я про бд летопись». Результат каждой клетки бэктеста лежит в `metric` — тех же строках, что и прочие числа записи; у клеток заполнены два новых столбца: `ckey` — канонический ключ клетки движка (отсортированная строка параметров) и `bin` — md5 бинарника движка (8+ знаков). У прежних строк оба пусты; `METRIC_COLS` и `h` прежних строк не менялись, повтор `metrics-import` их не пишет. Индекс `metric_cell(side, uni, win, ckey)`; строки только добавляются (те же триггеры), вид `metric_cur` читает последние.

- **Правило «сначала lookup, потом счёт»:** перед прогоном клеток спросить БД, что из них уже посчитано (`cells-lookup` / `cells_lookup`), и считать только недостающее; после прогона записать всё посчитанное (`cells_put`). Клетка = сторона × вселенная × окно × `ckey` × `bin`: другой бинарник — другая клетка (`--bin` / `bins=` ограничивает поиск нужными бинарниками, без него берётся последняя записанная, бинарник в строке).
- **API (скрипты на srv):** `sys.path.insert(0, "/data/chron"); import chron; st = chron.Chron(chron.connect(chron.SRV_DB))`; `st.cells_lookup(side, uni, win, ckeys, bins=None)` → `{ckey: строка}` (`extra` — разобран из JSON); `st.cells_put(L-N, rows, author=None)` → `{new, same, diff}`: одна транзакция, запись `L-N` должна существовать, строка = `{side, uni, win, ckey, bin, cell (подпись), trades, usd (Σ $ на ставку 500 $), mean_usd, sharpe, extra (прочие числа: метрики В-169, сделки по окнам…), src, src_ptr}`; `h = sha(side|uni|win|ckey|bin)`, повтор не пишется, `diff` — сколько повторов дали другие сделки / Σ $ (движок детерминирован — должно быть 0); битая партия не пишет ничего; пачка в 10 000 строк — около секунды. `st.cells_count(bins=None)`. С ПК те же операции идут по ssh (`chron.call("cells_put", …)`), CLI — `cells-lookup`, `cells-count`.
- `src` клетки — путь результата на srv, а не файл в git: `check` его не проверяет (проверяет только, что у клетки есть сторона, вселенная, окно и бинарник). В общем списке «Числа» (сайт, `metrics`), сводке полей и покрытии клеток нет (их тысячи): `metrics --cells` / `?cells=1` — только клетки, `metrics --entry L-N` — все строки записи; `stats` считает `metrics` и `cells` отдельно.

## Правила для тредов

1. **Новый вердикт, предрегистрация, поправка, заморозка — `chron.py add`, не строка в md.** `JOURNAL.md`, `EXPERIMENTS.md` и `P-*.md` не дописывать — это заглушки.
2. **Новый раздел протокола — `chron.py psec add`;** записанный до счёта — с `--prereg` (или `psec lock` до первого счёта). Изменить раздел «до счёта» нельзя — только поправка `--amends`.
3. Числа в записи — с меткой: `--same-data`, если найдено отбором на тех же данных; деньги — $ на ставку 500 $, Шарп — годовой по дневному. Числа по сторонам / клеткам / вселенным / окнам — `--metric` с источником (файл результатов), не текстом.
4. Ссылки — на всё, на что опирается вывод: раздел протокола, коммит, файл заморозки, отчёт, решение, карточка задачи. `chron.py check` перед слиянием.
5. Ошибка в записи — новая запись `--kind correction --corrects L-N`; старая остаётся, на сайте помечена «исправлена».
