## 3. Правила базы числами (`rl_*`, новые столбцы набора)

Источники — только то, что уже в наборе на момент сигнала строки; метки не участвуют.
| столбец | определение |
|---|---|
| `rl_base` | строка проходит конъюнкцию базы стороны (`L_base` для лонга, `S_base` для шорта): бит 1 `meta_base_pass` (сигнал строки есть в двойнике `L_ind` / `S_ind`: сделки + несостоявшиеся входы; фильтры двойника — `pk=1 pb=1 fh=4 fk=120 fm=50 fb=0.5 t24=12`, источник p60n2, `natr_min` 0,4 %, `t1h` 0,5 M — причинны, считаются движком по минутам ≤ t−1) |
| `rl_ref` | лонг: `L_n24` = `rl_base` ∧ `n24 ≥ 220000` (NaN → 0); шорт: `D_S` = бит 2 `meta_base_pass` (сигнал есть в двойнике `D_ind`, источник `lxD`) |
| `rl_c_natr`, `rl_c_t1h`, `rl_c_t24` | `natr_bp ≥ 40`, `turn1h ≥ 500 000`, `turn24h ≥ 12 000 000` (пороги — значения по умолчанию и `t24=12` из строки базы; NaN → 0) |
| `rl_c_n24` | `n24 ≥ 220000` (NaN → 0); у шорта константа, снимается обучением |
| `rl_n_base` | число выполненных условий базы, выразимых признаками: `[p60n2 в маске источников] + rl_c_natr + rl_c_t1h + rl_c_t24` (0…4) |
| `rl_n_ref` | лонг: `rl_n_base + rl_c_n24` (0…5); шорт: `[lxD в маске] + rl_c_natr + rl_c_t1h + rl_c_t24` (0…4) |
Условия `pk`, `pb`, «свежий уровень» (`fh/fk/fm/fb`) признаками набора не выражаются точно (замер 21.11 на признаках без меток: `since_touch_prior_h ≤ 4 ч` ∨ `cons120 ≥ 60` воспроизводит 85 % флагов лонга и 69 % шорта) — они входят в модель только через `rl_base` (флаг движка); в счётчик `rl_n_*` не входят. Все `rl_*` — «найдено на этих данных».
**G-rule (порог до счёта):** (i) у каждой строки с `rl_base = 1` — `rl_n_base = 4`, у каждой с `rl_ref = 1` — полный `rl_n_ref` (лонг 5, шорт 4) — 100 %; замер 21.11 на признаках без меток: 911 / 911 (лонг), 488 / 488 и 2 157 / 2 157 (шорт) — пороги `natr` 40 бп, `t1h` 0,5 M, `t24` 12 M выполняются у всех флаговых строк; (ii) `rl_base` и `rl_ref` равны битам `meta_base_pass` по построению (тест, печатаются числа строк); (iii) печатается доля флага среди строк с `rl_n_base = 4` (точность конъюнкции признаков). Красный (i) — стоп, отчёт, определение не меняется.

## 5. Выбор — причинный «топ-K в сутки»

Календарный «топ-K суток» требует оценок строк, пришедших позже в те же сутки, то есть заглядывания вперёд (в бою неизвестно); поэтому выбор — скользящий причинный эквивалент с тем же ожидаемым K в сутки:
- `R_base(m)` = число строк с `rl_base = 1` и `abs_ms ∈ [01.07, начало m − 24 ч)` ÷ число суток интервала; `R_all(m)` — то же по всем строкам. **K₁ = R_base(m)** (ожидаемо ≈ 6,3 строк/сутки лонг, 3,8 шорт — замер июля 21.11, только числа строк), **K₂ = 2·R_base(m)**; `q = K / R_all(m)`. Только счётчики, метки не участвуют; K и q считаются по месяцу m один раз до просмотра месяца проверки.
- Строка со временем `t` в часе `[h, h+1)` выбрана, если `score(t) ≥ τ_h`; `τ_h` — k-е по величине значение `score` у строк с `abs_ms ∈ [h − 24 ч, h)` (все строки, с меткой и без), `k = max(1, ⌈q·n⌉)`, `n` — число строк окна. Порог обновляется раз в час и не видит строк позже `h`; окно часов начала месяца содержит сутки разогрева (вне обучения, оценены моделью месяца).
- Выбранные строки **с меткой** идут в ту же реплику, что в §13.71 (`BASE_CFG`, `reentry = 0`, один уровень — одна сделка, старт 01.08 с пустым состоянием); строка без метки (вход не состоялся) места в портфеле не занимает.
- **Клетки вердикта (m = 6):** CatBoost лонг K₁, лонг K₂, шорт K₁, шорт K₂; LightGBM лонг K₁, шорт K₁ — против базы своей стороны (`L_base` / `S_base`). Справка вне Холма и вне счётчика: те же клетки против `L_n24` (лонг) / `D_S` (шорт). Нулевая модель — для всех 6 клеток, плацебо — для 4 клеток CatBoost.
Печатается рядом: выбранных строк в сутки (по месяцам) против K, принятых сделок против базы (G-K — описательные, не ворота).

## 9. Правило вердикта (на клетку; как §9 PS-948, m = 6)

«**Добавляет к базе** (найдено на этих данных; кандидат только вперёд)»: односторонний p парной суточной Δ за авг–ноя ≤ шага Холма (m = 6); Σ и годовой Шарп клетки ≥ базы; Δ > 0 минимум в 3 из 4 месяцев; ≥ 30 сделок минимум в 3 месяцах; ΔΣ > 0 без 2 лучших суток и без 2 лучших монет. «**Не добавляет**»: точечная ΔΣ за авг–ноя ≤ 0. Иначе «не ясно» (с MDE). Просадка и перехай не гейт, но рядом с базой в вердикте (§В-169). Что делаем: «Добавляет» — кандидат вперёд (В-165), не торговля; «Не добавляет» во всех 6 клетках — направление «модель поверх базы на всём наборе» на этих данных закрыто, развилка дальше — координатору.

## 13. Решения исполнителя на утверждение критика (развилки; В-165)

1. Выбор — причинный скользящий порог вместо календарного «топ-K суток» (п. 5): календарный заглядывает вперёд. Отступление от формулировки брифа, записано.
2. K₁ — строки базы в сутки (до реплики), а не принятые сделки базы: реплика отсеивает ≈ половину строк (L_base: 690 сделок двойника → 327), и «то же число кандидатов в ту же реплику» честнее равенства принятых; принятые сделки печатаются рядом.
3. N\* по AUC проверки июля (классификатор), не по Logloss: веса классов сдвигают вероятности, AUC — нет.
4. `rl_n_*` считает только выразимые признаками условия (источник, `natr`, `t1h`, `t24`, у лонга ещё `n24`); `pk`, `pb`, «свежий уровень» — только через `rl_base`.
5. LightGBM — клетки вердикта (K₁, лонг и шорт; FIX критика: владелец спросил прямо «Может другое попробовать? Лайт или xg?», справка на него не ответила бы), m = 6, счётчик 40, планка 4,08; K₂ для LightGBM не считается. **XGBoost не считаем:** это ещё одна библиотека градиентных деревьев на тех же строках и той же цели — контроль, а не новая идея; ответ владельцу на «Лайт или xg?» даёт LightGBM, и если CatBoost и LightGBM дадут близко, XGBoost этого не объяснит.
6. Подвыборки обучающих строк нет (§13.71 брал 50 % при > 600 k): все строки, 150–700 k.
