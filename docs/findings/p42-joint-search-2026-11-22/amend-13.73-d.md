Поправка к §13.73.2 (PS-955): ось `split` — вход двумя частями (В-171, TK-677) — в карте пар; стоп 5 % в клетках с частью B «за тик до уровня». Записана ДО счёта клеток оси.

## 1. Зачем

Слова владельца (В-171, дословно): «мне кажется что для того чтобы снизить стоп надо разделить позицию на две типа входим заранее и прямо за тик до уровня» · «и этот параметр нужно добавить в комбинаторику» · «вдруг у нас при этом параметре и стоп в 5% будет не страшен так как стоп в 5% на пол позы это 2.5%» · «это надо не отдельно а с чем то перебирать». Движок с ключами разделённого входа — TK-677 (ветка `bb/tk-677-split-entry-v1-thr_hgrv7c5qqt` @ `191d3b96a`, бинарь `/data/p42-tk677/bin/alpha-tk677.93cb51a9`, md5 `93cb51a92560f7c2a3098d77d0709e53`; G-base — 6 строк баз × 4 файла байт в байт с бинарём карты, `/data/p42-tk677/res/gbase674.json`).

## 2. Ось (значения фиксированы до счёта)

Одна составная ось `split` (класс «вход»), ключи движка: `e2` (часть B на расстоянии e2, как раньше), `e2t` (часть B за N тиков до уровня), `w2` (доля части B, % ставки), `s2` (1 — общая цена стопа обеих частей). Значения:

| метка | e2 | e2t | w2 | s2 | смысл |
|---|---|---|---|---|---|
| `off` | 0 | 0 | 50 | 0 | один вход (база лонга) |
| `e2w25` / `e2w50` / `e2w75` | 0,05 | 0 | 25 / 50 / 75 | 0 | часть B на расстоянии e2 (`e2w50` — база шорта) |
| `t1w25` / `t1w50` / `t1w75` | 0 | 1 | 25 / 50 / 75 | 0 | часть B за тик до уровня |
| `t2w50` / `t3w50` | 0 | 2 / 3 | 50 | 0 | часть B за 2 / 3 тика (за 1 тик часть B исполняется меньше чем в половине сделок — замер TK-677 без P&L: лонг 256 из 574, шорт 206 из 433) |
| `t1w50s2` | 0 | 1 | 50 | 1 | за тик, общая цена стопа |

База оси: лонг `off`, шорт `e2w50` (строки баз' не меняются). Пары: `split` × каждая из остальных осей, кроме `e2` (ось сама задаёт e2) — 33 пары на сторону; остальные правила совместимости и допустимости клетки — §13.73.1; меньшая часть входа при w2 ≠ 50 должна давать ступень тейка ≥ 5 $ (недопустимые отвергает разбор движка, стадия `validate`).

## 3. Стоп 5 % и охрана (д) в клетках оси

- Стоп 5 % остаётся справочной колонкой везде, **кроме клеток с частью B «за тик до уровня» (e2t > 0)**: там s = 5 % — обычная клетка перебора (В-171). В парах `split` × `s` значение 5 % считается; в клетках `off` / `e2w*` при 5 % — справка, как в §13.73.2.
- Для клеток с e2t > 0 охрана (д) — два условия, нужны оба: (1) убыток по цене стопа случая «сработала только часть A» = (100 − w2) % × 500 $ × s + 0,415 $ ≤ убытка по цене стопа базы' (лонг 15,41 $, шорт 20,41 $); (2) средний реальный убыток сделки, закрытой по стопу (все stop-выходы клетки, $ на сделку целиком) ≤ того же. Для остальных клеток (д) — как в §13.73.2.
- В отчёте у каждой строки с e2t > 0 рядом печатаются: убыток по цене стопа случая «A + B» (вся ставка, 500 $ × s + 0,415 $), число стопов «A + B» и «только A» со средним $ каждого вида (из `<сторона>-lots.csv` движка), доля сделок с исполненной частью B, худшая сделка; R:R — первыми колонками.
- Соседи плато (г) по оси `split` — явно: w2 25 ↔ 50 ↔ 75 внутри одного семейства (`e2w*`, `t1w*`); e2t 1 ↔ 2 ↔ 3 при w2 = 50 (`t1w50` ↔ `t2w50` ↔ `t3w50`); `t1w50` ↔ `t1w50s2`; `off` ↔ `e2w50` и `off` ↔ `t1w50`. Остальные охраны, победитель пары, прирост над базой' — без изменений.

## 4. Бинарь

Клетки оси считает бинарь TK-677 (`TK674_BIN`, `TK674_GBASE`). Перед счётом — выборочная проверка `spot`: три готовые клетки карты (выход, сигналы, фильтр; окно wa, лонг) новым бинарём — файлы сделок байт в байт с прежними; при успехе md5 нового бинаря добавляется в `res/eqbins674.json` (клетки обоих бинарей — один набор), при расхождении — стоп. Клетки без новых ключей не пересчитываются.
