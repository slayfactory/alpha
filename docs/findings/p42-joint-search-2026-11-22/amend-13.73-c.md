Поправка к §13.73.2 (PS-955): тройки осей — правило отсечения, чтение и счётчик; порядок для четвёрок. Записана ДО чтения карты пар с базой стопа ≤ 4 % и ДО счёта троек.

## 1. Зачем

Постоянный приказ владельца (В-171, дословно): «как переберешь всен двойки и ди на тройки. как закончатся тройки иди на чептверки». Все тройки без отсечения — лонг 125 582 клетки (считать 121 065), шорт 138 252 (133 445), 3 195 + 3 517 проходов сигналов: по замеру пакета пар (≈ 1,05 с движка на клетку по трём окнам) это ≈ 74 ч движка и ≈ 34 ГБ, а шум выбора при m ≈ 130 000 на сторону ≈ 7,3 Шарпа. Поэтому уровень считается с отсечением, правило — ниже, до просмотра карты пар §13.73.2 (пакет `tk674b-chain` на момент записи идёт, карта не прочитана).

## 2. Правило отсечения троек (механическое, по карте пар §13.73.2)

1. **Планка осей пары** — наибольший Шарп из: база' стороны; лучшая охранённая (а)–(д) клетка, где сдвинута только первая ось пары; то же для второй оси (`best1` карты; клетки со стопом 5 % не участвуют).
2. **Активная пара** — у пары есть охранённая (а)–(д) клетка с плато (г), где сдвинуты обе оси, и лучшая такая клетка (правило победителя §13.73.1) имеет Шарп строго выше планки осей пары и Σ не ниже Σ базы'. Прирост пары = её Шарп − планка. Пара, в которой всё делает одна ось, активной не становится.
3. **Тройка осей допустима**, если все три её пары совместимы (правила §13.73.1). **Тройка берётся**, если активны не меньше двух из трёх её пар.
4. **Порядок и потолок:** взятые тройки упорядочены по сумме приростов активных пар (убывание, при равенстве — по имени); сетки троек (все значения трёх осей, те же охраны допустимости клетки; у оси `s` — только значения не выше базы стопа стороны: лонг 1; 1,5; 2; 3, шорт 1; 1,5; 2; 3; 4 — стоп выше базы' охрану (д) не проходит по построению и в тройках не считается, справочная колонка 5 % берётся только из БД, если клетка там есть) набираются целиком в этом порядке, пока число новых клеток стороны (нет в БД) ≤ **20 000**; первая тройка, которая не помещается, и все после неё не считаются. Число прошедших правило, взятых и оставшихся за потолком печатается в отчёте. Если правило даёт 0 троек на стороне — уровень стороны закрыт записью «активных пар нет», четвёрки на этой стороне не считаются.
5. Ось `split` (TK-677) входит в это же правило, когда её пары появятся в карте (отдельная поправка оси); до этого тройки считаются без неё, а тройки с `split` досчитываются дельтой по тому же правилу.

## 3. Чтение уровня

- База', охраны (а)–(д), стоп 5 % — только справочная колонка — как в §13.73.2. Плато (г) — соседи на шаг по каждой из трёх осей.
- Победитель тройки — правило §13.73.1 (наибольший Шарп среди охранённых с плато; при разнице ≤ 0,1 — короче самый долгий перехай, затем меньше просадка). Рядом — лучшая охранённая клетка с плато, где сдвинуты все три оси.
- **Планка нижних уровней тройки** — наибольший Шарп из: база'; `best1` трёх осей; лучшая охранённая (а)–(д) клетка каждой из трёх пар тройки. «Тройка добавляет» = лучшая клетка со всеми тремя сдвинутыми осями выше этой планки и Σ не ниже Σ базы'. Это описание («найдено на этих данных»), не доказательство: рядом печатаются m, шум, число троек выше планки.
- Отчёт — одна строка на набор сделок; первыми R:R и убыток по цене стопа, рядом худшая сделка, Σ $, $ на сделку, число сделок, Шарп, просадка, перехай (самый долгий / средний / хвост). Без медиан, без бп. Строки не складываются — торгуется одна линия.
- Ничего не замораживается; кандидаты вперёд — только отдельной поправкой (§13.73.1 разд. 6).

## 4. Счётчик испытаний и шум

m стороны = все клетки стороны в БД на момент чтения (после §13.73.2: лонг ≈ 9 653, шорт ≈ 10 206) + новые клетки троек (≤ 20 000) → ≤ ≈ 29 700 / 30 200. Шум = σ Шарпа клеток уровня × √(2 ln m), при σ ≈ 1,5 — ≈ 6,8 Шарпа (верхняя оценка, клетки зависимы). Неотобранные тройки в m не входят: на них не смотрели.

## 5. Стоимость и запуск

После конца пакета пар: `tk674_level.py select 3 20000` (TK674_REBASE=1; читает только карту пар и ключи в БД, без P&L новых клеток) → таблица «есть / считаем» по сторонам, проходы сигналов, часы srv — критику до запуска. Оценка сверху при полном потолке: 40 000 клеток × 1,05 с ≈ 11,7 ч движка (стороны — двумя процессами параллельно, ≈ 6 ч по часам) + таблицы; место ≈ 5,3 ГБ. Один пакет: юнит `tk674b3-chain` (`systemd-run`, Nice 19, движок 2 потока на сторону, таблицы 3 процесса), `TK674_REBASE=1 TK674_LEVEL=3`; стадии `ftab` (составные фильтры клеток уровня, пороги — готовые `thr674.json`) → `validate` → `cells` → `tables --entry L-<запись>` → `ccheck` → `tk674_level.py map 3` → `tk674_mapmd.py --suf b3`. Найденная в БД клетка не пересчитывается.

## 6. Четвёрки

Тем же порядком после карты троек, без новой поправки к правилу: активная тройка — лучшая клетка со всеми тремя сдвинутыми осями выше планки нижних уровней и Σ ≥ Σ базы' (прирост = Шарп − планка); четвёрка берётся, если все её пары совместимы и активны не меньше двух из четырёх её троек; порядок — по сумме приростов активных троек; потолок 20 000 новых клеток на сторону; планка нижних уровней четвёрки — база', `best1`, лучшие охранённые клетки её пар и посчитанных троек; плато — по четырём осям. Перед запуском — поправка `psec add … --amends <раздел §13.73.3> --prereg` с таблицей «есть / считаем», часами и списком взятых четвёрок (критик). 0 четвёрок по правилу — уровень закрыт записью.
