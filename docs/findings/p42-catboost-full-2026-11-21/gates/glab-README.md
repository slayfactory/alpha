# G-lab (TK-671), определение после правки 21.11 (до PASS критика)

Протокол §13.71: «G-lab метка строки = сделка той же строки из независимого прогона 200 строк». Исполнение: независимый прогон = двойник базы (`L_ind` / `S_ind` / `D_ind`, `tk671_twin.sh`, те же сигналы и выходы).
Первое определение (ключ `(sym, sig_ms, entry_px_e8)`, без среза зачётного диапазона) было неверным: ключ неоднозначен, в файлах двойников сутки соседних окон — давало 76–85 % найденных и «расхождения» на чужих строках.

Определение после правки: сделки двойника с `lo_ms ≤ sig_ms < hi_ms` (диапазон окна, как у баз); «найдено» = есть строка-кандидат с меткой по ключу; «точно» = среди кандидатов есть строка с теми же net, entry_ms, exit_ms, kind.
Ворота: найдено ≥ 95 %, точно = 100 % найденных, найдено ≥ 200. Результат: L_ind 883/885 (883 точно), S_ind 448/451 (448), D_ind 1 779/1 779 (1 779). Расхождений по полям среди найденных — 0.

Ненайденные (5 сделок, ключи в `glab-long.json` / `glab-short.json`, поле `missing`): у `(sym, sig_ms)` нет строки ни в одном из 12 источников и в дампе p60n2 нет сигнала монеты в ±10 мин. Причина (замер по одной монете и окну на каждую ненайденную сделку, одна нить; `glab-diag-pkpb-variants.txt`, `glab-diag-pkpb-short.txt`): двойник с `pk=1 pb=1` даёт эти сигналы (лонг PUMPUSDT wb: 2 из 2; шорт BEUSDT wa: 2 из 2, KATUSDT wc: 1 из 1), тот же двойник с `pk=0 pb=0` — ни одного из 5 (остальные источники дампа идут без pk/pb). То есть уровень в базе появляется, только когда pk/pb убили более ранний уровень, — известное ограничение набора строк (G-cov-base ≥ 97,96 %).
