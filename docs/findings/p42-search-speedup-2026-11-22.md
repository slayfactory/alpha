# П-42: где время и память партий совместного поиска и что ускорено (TK-683, 22.11.2026)

Слова владельца 22.11: «ниче не ускоряется?». Движок — `breakout tick`, как его зовёт `tools/p42/tk674_run.py cells` (srv, 8 vCPU, 62 ГБ).
Все числа измерены; торговых выводов нет. Карточка — `kb/task/TK-683.md`.

## Куда уходит время и память

Время — по журналам 910 вызовов движка карты TK-674 (`/data/p42-tk674/log/cells-*.log`, 246 268 вариант-окон, 66,9 тыс. с движка, `--threads 4`);
разбор внутри фазы 2 — `perf record` на малом входе (63 монеты из 775, окно wa, 2 потока, юнит `tk683-prof`, MemoryMax 6 ГБ).

| Фаза 1 — проходы сигналов | 24 % | 15,5 тыс. с; 1,22 с на проход-окно; 12 880 проходов, из них разных 6 740 (`--sig-cache` скрипт не передаёт) |

| … прочее в фазе 2 (ход по сделкам, запись файлов) | ≈ 9 % | 0,018–0,033 с на вариант-окно в партиях без `e2t` / `mk` |
| Python между вызовами | < 1 % | таблицы пар 85 с на 2 ч 26 мин движка (карточка TK-674) |

Почему бинарь split стоил 4,2 с на клетку против ≈ 1 с: ключ `e2t` (и `mk`) на каждый вход зовёт `tick_at`, а она каждый раз заново шла по всем
сделкам суток входа и семи предыдущих суток; память результатов жила только внутри одного варианта.

Почему 26 проходов: это предел `SIGMAX = 26` в `tk674_run.py`, выбранный по памяти, а не свойство движка.
