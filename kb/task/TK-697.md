## Критик

- без заглядывания: только закрытые минуты строго до минуты сигнала (как `tk638` window);
- «к пробою» — знак по стороне;
- расстояния в NATR60 и в %;
- пороги — квантили q20 / q40 / q60 / q80, ≥ и ≤, по всем строкам кандидатов, заморожены (как TK-680 / 681);
- NaN проходит, X печатается (PS-993 (д)).

### Критик 23.11: отрицательные `age_h` / `approach_dur_min` в таблице TK-671 — дефект (единицы баров)

Воспроизведено независимо (измерено, `/data/p42-tk671/asm/*.parquet`): отрицательные `age_h` = `approach_dur_min` в одних и тех же строках — wa-long 212 999 / 313 835, wa-short 185 056 / 270 681, wb-long 155 143 / 226 756, wb-short 134 421 / 195 273, wc-long 162 482 / 239 505, wc-short 155 503 / 225 209; `since_born_h` < 0 — 0 во всех файлах.

Причина — не база, а единицы. `breakout::levels` пишет `first_bar` и бары членов (`members`) в барах ТФ варианта (`cfg.tf_min` = 30 / 60 / 240), `born` — в минутах. Rust f12 (порт TK-611, 19.11) жёстко ставит `const TF: i64 = 60` (`src/breakout/feat/f12.rs:36`); у Python `sigfeat_lib.level_features` есть параметр `tf_min`, при порте он потерян. По `meta_src` (wa-long): источники 0–2 (p30n1–3) — 100 % отрицательных (возраст занижен: `first_bar·60` вместо `·30`); 6–8 (p240n1–3) — 0 % отрицательных, но возраст завышен (медиана 807–871 ч вместо десятков); 3–5 (p60) и 9–11 (lx) — верно. Проверка по свечам (`/data/p42-tk621/wa/cache/*.b42`, 20 строк sigsx, seed 697): цена каждого члена равна максимуму бара только при ТФ своего варианта — p30 7/7 только при 30, p240 7/7 только при 240, p60 6/6 только при 60; истинный возраст ≥ `since_born_h` во всех 20 (пример ZKC: f12 −1 368 ч, верно 3,0 ч, `since_born_h` 1,4). Инвариант по всем строкам sigsx: `born − first_bar·tf` ≥ n·tf (90 / 180 / 720 мин и т. д.) только с ТФ варианта.

Объём. Неверны на строках p30 / p240 все признаки на `first_bar` / барах членов: `age_h`, `approach_dur_min`, `pierce_ep`, `pierce_max_bp`, `touch_ep`, `since_touch_h`, `depth_min_bp`, `depth_mean_bp`, `since_touch_prior_h`, `touch_prior_none` (10 столбцов); `since_born_h`, `n_piv`, `spread_*`, `ext_gap_bp`, `dist_bp` и признаки свечей у сигнала — верны. Затронуто всё, что читает `/data/p42-tk671/asm` или `/data/p42-tk671/data`: TK-671 (CatBoost), TK-672, TK-680 (оси), TK-685, TK-690, TK-674 и TK-697. В TK-674: столбцы шорта с этими единичками — 24 100 из 118 265 (`ftabcols674*`; шаг 3 — 630 из 4 284, основа шага 4 — 170, r02–r13 — 967–2 919 на партию, `6744r05` — 10); у лонга — 0. Токены: `pierce_max_bp<=0`, `touch_ep<=0..3`, `approach_dur_min>=-55000`, `>=0` — порог −55 000 мин подобран на сломанной шкале, по смыслу это фильтр «источник не p30». Строки базы TK-674 на `data/*.parquet` — смесь источников (шорт wa: p30 152 из 279 совпавших). База h775 (`/data/p42-tk634/feat/h775`, TK-654) — 0 отрицательных, эти столбцы не из f12 с ТФ 60 → не затронута. Верхние строки L-384, L-360 / L-361, якоря L-334, пары L-353 (лучшая `s4+N24_q20+sac10…`) — оси движка и N24 / sac, единичек из списка нет → не зависят (по тексту записей; по клеткам подтверждается выборкой при пересчёте).
