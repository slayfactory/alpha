## Что есть в движке (по коду, до правки)

- Лот 1: тейкер по ленте (`ew`) или лимитка `mk` — `mk1`: лимит = последняя сделка стороны − тик, `mk2`: уровень без сдвига, заявка рабочая только после пробоя.
- `e2` / `e2t` — только лот 2 (часть B, у уровня), доля `w2` 5…95; лот 1 остаётся тейкером / мейкером от последней сделки.
- Ни один ключ не ставит всю ставку одной лимиткой на цене `L ∓ N·тик` → ключ `e1t`.

## Ключ `e1t` (только до уровня, В-178)

`e1t = N`, целое 0…1000 (значения оси 1 / 2 / 3; 0 — выключен, строка `params` в `meta.json` тогда прежняя байт в байт; отрицательное — отказ валидации). Требует `ew > 0` (допуск по ленте `Stale` / `Beyond`, как у `mk`); несовместим с `mk`, `ek`, `xb`, `e2`, `e2t` (и значит `w2`, `s2`), `pw`. Только `breakout tick`. Тик — `tick_at` на момент постановки заявки (нет тика — отказ `NoTick`). Вход — мейкер: комиссия мейкера, проскальзывание входа 0, счётчики заявок — `<сторона>-maker.json` (`filled / unfilled / touched`, как у `mk`). Лот один, вся ставка.

Геометрия заполнения (в раме: лонг — цена как есть, шорт — цена со знаком минус, «выше / ниже» ниже — в раме; для шорта цены зеркальны):

- Заявка ставится в `сигнал + lat`, живёт до конца минуты этого момента (допущение модели: как у `mk`; продление — отдельным решением). Цена лимита `limit = grid(L) − N·тик`, где `grid(L)` — уровень `L`, округлённый вниз на сетку последней сделки стороны (как у `mk2`). `p_sur` — последняя сделка стороны ≤ момента постановки (окно `ew`).
- Лимитная покупка стоит в книге мейкером, только пока рынок не ниже лимита (выше рынка она исполнилась бы сразу тейкером — этого в модели нет): если `p_sur ≥ limit` — заявка стоит с момента постановки; иначе — с первой сделки любой стороны `p ≥ limit` плюс `lat` (зона `limit ≤ p < L` — как у `e2t`: `p ≥ L − N·тик`, `p < L`). До этого момента заполнений нет.
- Заполняет первая сделка строго позже момента «заявка стоит» с ценой строго ниже лимита (сделка на цене лимита — очередь впереди — не заполняет); вход по цене лимита, время — время сквозной сделки (как `mk1`).
- Сделка `p ≥ L` до заполнения снимает заявку (`Touched`); если `p_sur ≥ L` при постановке — тоже `Touched`; после заполнения касание ничего не меняет. Нет сделок в зоне / ниже лимита за минуту — `Unfilled`. Отказ — как у `mk`: монета не занята, уровень не потрачен.
- За уровнем (`N < 0`): в коде `e1_decision` знак понимает (мейкер-заявка выше уровня, заполняет возврат цены — ретест после пробоя; тесты на уровне решения), но ключ отрицательное отвергает (В-178), в карту оно не идёт.
