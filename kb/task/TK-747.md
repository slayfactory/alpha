Ключи (все выкл. по умолчанию; поля `LevelCfg::{lm, lz}`, `SigCfg::{fw_min, fz_min}`; в текст ключа кэша и в `Debug` входят только при включении; в `breakout run` отвергаются, `reject_tick_only`):

- `lm=1` — уровни без средних. Слово владельца 28.11 (добавка): «я же сказал что уходим от среднего» — среднего нет нигде: цена уровня — крайний пивот по ходу пробоя (шорт — самый низкий минимум), допуск `tau` группы мерится от цены этого пивота (`levels.rs::group_ok(.., lm)`), у каждого члена своя цена (setup.csv, роль `touch`). `P_far` в коде — противоположный крайний (`far_edge`: у шорта самый высокий минимум); в брифе `P_far` назван иначе — реализовано по формулировке «крайний по ходу пробоя».
- `lz=1` — закол: группа ровно из двух пивотов, где более поздний (по бару) строго дальше раннего по ходу пробоя, не рождается; пивоты остаются в `free` (с третьим — каскад, не отменяется). Шаг цены в движке не известен — «строго» (цены кратны шагу).
- `fw=<мин>` — свежесть по владельцу вместо (а) / (б): `tick.rs::fresh_fw_ok` — ≥ `fw` мин после постановки (подтверждение последнего присоединившегося пивота, `Level::fresh`), проторговка по `fm / fk / fb` в окне `[max(постановка, t − fk), t)`, касание после постановки (`touched` ведёт `candidates_group_tr`). Требует `fm > 0`, `fh = 0`, `fw ≤ fk`.
- `fz=<часы>` — разрыв «много времени после старых уровней» (при `fw > 0`): расстояние от пивота, поставившего уровень, до ближайшего по времени из прочих членов ≥ `fz`; по умолчанию 0 (срок владелец не назвал, В-196).

Файлы: `src/breakout/{levels,params,tick,sigcache,cli}.rs`, тесты — `src/breakout/tick_tests/owner_tests.rs` (по случаю на ключ + проверка ключа кэша; `sigcache_tests.rs` дополнен), `docs/COMMANDS.md`, `tools/p42/tk674_axes.py` (ключи в `DEFAULTS` / `SIG_KEYS`), гейт `tools/p42/tk747_gate.sh`.
