## Статический разбор кода (агент Explore, 25.11; файл:строка в `src/breakout/`)

- **Сортировки / поиски / хеши.** Вызов: `cache_files` sort (data.rs:566). Задание сигналов: `sort_tsigs` n log n по 56-байтным `TSig` (tick.rs:1228, после каждого пересчёта, пропуск при hit); `signals_for_coin` — `HashMap<(SigCfg,Side),_>` с клонами `SigCfg` ≈ 250 Б + SipHash на каждый сигнал (`lev[&(cfg.lv.clone(),side)]`, tick.rs:1176); `BTreeMap by_day` на кандидата (1137); `minute_range` 2× `partition_point` на кандидата на задание (1078); `next_px` обходит все уровни на каждый сигнал (levels.rs:177). Вариант: `job_idx` HashMap с клоном `SigCfg` 2–3 раза на (вариант, сторона) (tick_cli.rs:574-585); `consumed: HashSet<u64>` SipHash на сигнал (tick.rs:3265, 3359); `open.remove(0)`, `open.sort_by_key` на сигнал; при `pr>0` — копия и сортировка сигналов на вариант. `ZipSrc::day` на КАЖДЫЙ вызов: `sym.to_string()` + глобальный `Mutex<Lru>` + HashMap `(String,usize)` — 2–3 раза на сигнал на вариант и на каждую смену суток в курсоре (tick.rs:571-645, 1839) — кандидат на «дёшево».
- **Ширины.** `Tick` 12 Б (packed 4: `px i64` + `ob u32`), `TSig` 56 Б, `Cand` 24 Б, `Sym` 48 Б/мин/монета (5,53 МБ на монету, `Vec<i64>` o/h/l/c/qv/pq; 115 200 мин) + ленивые ряды до ≈ 9,4 МБ на монету. `Pos` — i64; `ExitCfg` ≈ 380 Б, на сделку читаются только `ex.tl` и `ex.lat_exit_ms`. i128 на сделку: только `NatrStop::dist` при `sn_m > 0` (tick.rs:1448-1462; `unit·k0` до 5e21 не влезает в u64, но `nat` не зависит от сделки → вынести в `Pos::new`); `ek_decision` (i128, влезает в i64); фаза 1: `rv_of` (u128 префиксная сумма + isqrt на минуту; влезает в u64 при окне r² < 1,8e19), `natr_of` (i128 запасной путь только для цен > ≈ $15 тыс.), `group_ok` (i128, влезает в i64 при цене < $900 тыс.), `levels` lx=4 `Line::fit` — i128 нужен. f64 в фазе 1 нет.
- **Минутки (загрузка).** `.b42` ≈ 4,6 МБ на монету (магия + 5 колонок i64 LE по 115 200 + финансирование), без сжатия; `fs::read` целиком + 5 копий `chunks_exact(8).collect()` + `pq` префикс; `par_map` по файлам на `threads`. На КАЖДЫЙ вызов заново: чтение и разбор всех `.b42` (даже при полном hit кэша сигналов — фаза 2 нуждается в `Sym`), `natr_of` / `rv_of` / `bars_of` (ленивые, в фазе 1 под `OnceLock`), `build_levels_far` на (монета, LevelCfg, сторона) (не кэшируется между вызовами), `SigCache::open` (читает ВЕСЬ исполняемый файл + sha256, `unzip -v`, ≈ 81 `metadata` на монету). Общий `Arc<Vec<Sym>>` на партию = пропуск повторов.
