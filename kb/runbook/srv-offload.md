Цепочка (TK-608, [[В-155]]; текст перенесён из `docs/COMMANDS.md` 24.11, TK-705): `collector-day-upload.timer` (каждый час, :17) → [[storage-box]] `alpha/collect/<биржа>/<день>/` с sha256 каждого файла → **`collector-offload-delete.timer` (каждый час, :47)** удаляет на [[srv]] закрытые сутки, сверенные на боксе (с 23.11 сразу, `--keep-hours 0`, TK-694: `arb-live` остановлен). Скрипт `/opt/day-upload/offload-delete.py --keep-hours 0 --sample 20 --go` (до TK-694 — 37; в репозитории — [[tools/srv-offload-delete.py]], юниты `tools/collector-offload-delete.{service,timer}`; до TK-608 — раз в сутки в 02:30 и «оставить 3 суток»).

- **На srv остаётся:** текущие сутки (≈ 17 ГБ к концу дня) (с 23.11, TK-694) — только они; до этого ещё и сутки с данными моложе 37 ч под окно `arb-live` (`arb-live` и `arb-turnover` остановлены, [[В-180]]; вернуть вкладку: `systemctl enable --now arb-turnover; systemctl start arb-live`, затем `--keep-hours 37` в `/etc/systemd/system/collector-offload-delete.service` и `systemctl daemon-reload`).
- **Сутки удаляются только при всех условиях:** `.ok` в `/data/upload-state/<биржа>/` равен локальным файлам (размер + mtime); на боксе совпали имена, размеры, число файлов и сумма байт; у случайных 20 файлов sha256 пересчитан заново и равен `sha256sum` на боксе; нет файла моложе 15 мин. Коллекторы не трогаются.
- **Журнал:** `journalctl -u collector-offload-delete` (строки `DEL` / `SKIP`). План без удаления — `systemd-run --wait --pipe -p Nice=19 -p IOSchedulingClass=idle python3 /opt/day-upload/offload-delete.py --keep-hours 0`. Выключить — `systemctl disable --now collector-offload-delete.timer`.
- **Вернуть сутки:** `rsync -a box:alpha/collect/<биржа>/<день>/ /data/collect/<биржа>/data/<день>/` (для `bybit` корень — `/data/turbo-probe/soak-bybit/data`).
- **Холодные каталоги `/data/<имя>`:** [[tools/srv-offload-dirs.py]] — один `rsync -aH` на набор, сверка (число файлов и ссылок, байты, повторный `rsync -n`, sha256 выборки), `--delete` только после сверки; запуск только через `systemd-run`; отказывает на защищённых и занятых каталогах (запущенный юнит / процесс). Манифест 18.11 — `docs/findings/srv-offload-2026-11-18.md` (каталог → путь на боксе `/home/offload-srv-2026-11-18/<каталог>`).
- **Любой путь, часть оставить (TK-675, 22.11):** [[tools/srv-offload-paths.py]] — список `{src, dest, exclude}`, по очереди: отказ при занятости → сводка → `rsync -aH` → сверка (файлы, ссылки, байты, `ls -lAR` бокса без исключённых поддеревьев, `rsync -aHn` без отличий, sha256 выборки) → сводка ещё раз = до копии → удаляются только перенесённые файлы и ссылки. `--delete` сам делает обход `--preflight` (ссылки из остающегося на srv, включая исключённые поддеревья, в переносимое) и при находке ничего не копирует и не удаляет. **Сначала `--preflight`:** окна счёта (`p42-tk621/{wa,wb,wc}`, `p42-tk599/{wa,wb,wc}`, `p42-tk616/fwd`, `p42-tk625/h775`, `p42-tk604/w0`) состоят из ≈ 280 тыс. симлинков на сырьё (`/data/aggtrades/binance`, `/data/p42-past`, `/data/p42-past06`, `/data/p42-tk596/dl`, `/data/p42v2/cache`), а `breakout tick --trades <окно>/aggtrades` читает их при каждом счёте — перенос цели оставил бы ссылки висеть. Несколько путей можно гнать параллельно отдельными юнитами со своим spec (один поток к боксу ≈ 5 МБ/с; в `--only` путь не писать — юнит с этим путём сам станет «занятым»).

- **Сырьё aggTrades-zip → пустышки (TK-694, 23.11):** `tools/srv-zip-stub.py` — у zip с действительным `.tk` склада тиков (размер + mtime = заголовок) данные уходят на бокс, а на месте остаётся разрежённый файл того же размера и mtime (0 блоков): движок, отпечаток кэша сигналов и `store-fill` читают у zip только `size` + `mtime`. `manifest ЛОК=БОКС … --store СКЛАД --out M.jsonl` (sha256 локально, на боксе и по `.CHECKSUM` / `.sha256`), `stub M.jsonl --store СКЛАД --go`, `restore M.jsonl [--only ПОДСТРОКА]` (с бокса, sha256 и mtime из манифеста).
