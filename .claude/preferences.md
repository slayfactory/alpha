# Постоянные приказы владельца (вставлять в каждый бриф)

Решения — `kb/decision/` (`AGENTS.md`); новое слово владельца — сразу карточкой В-<следующий номер>, дословно. Слова и случаи по пунктам — `docs/plan/preferences-why.md`.

1. Владельцу — только деньги, направление, риск, необратимое; методика, числа до счёта, развилки исследований, уборка веток и кода — координатор и проверяющий (В-39, В-48, В-53).
2. Прямой приказ («стоп», «удаляй», «запускай») — сразу, дословно, без переноса и смягчения; неясен срок или объём — спросить, не выбирать; недостающее помечать «считается/на проверке», зависимости в срок не складывать.
3. Сырые данные не удалять без слова владельца (приказано: датасеты на srv и Storage Box, В-131, В-132).
4. Ответ владельцу — по-русски, сначала результат и число, потом смысл и следующий шаг; GMT+4; числа — по п. 9. Статус — числа, сделано, идёт, срок, без воды и терминов, даже на одно слово «статус». Без прогнозов «стоит / не стоит». Расход токенов и $ — только если спросил (токенами). Без повторов итогов и «ещё идёт». Сообщения владельцу (В-163, 20.11): только результат, нужное решение, сдвиг срока, авария; промежуточные «идёт / критик PASS / технический FIX» не пересказывать (максимум одна строка); ответ ≤ 5 строк, таблица — только для результата; без повторов уже сказанного и без хвоста про /clear в каждом сообщении. Событие треда без новостей для владельца — ответ одним номером задачи (например «TK-638»), без текста (20.11).
5. Сроки — в темпе Claude Code (код / сборка+тесты / гейт / итого), GMT+4 по `date`, «дни» не называть; самое короткое время по задаче, без запаса; без разбивки (шаг → минуты → время готовности) срок не называть.
6. Алгоритм оптимальный, не первый: узкое место → лучшие способы → замер на малом → выбор без потери качества (SETTLED В-170); в отчёте исполнителя строка «Алгоритм: варианты — …; замер — …; выбран — … потому что …», без неё отчёт возвращается; перед счётом убрать лишние старые шаги. Движок счёта: ускорение — с гейтом «байт в байт», боевой бинарь — PGO (В-32); коллекторы — без гейта против Python (В-150).
7. Обходы (аренда, покупка серверов, найм) не предлагать — ускорять метод (SETTLED В-159).
8. ПК владельца — без тяжёлого счёта, сборок, браузерных прогонов (headless Edge / Chrome); cargo запрещён хуком. Сборки и проверки — srv и София (В-103).
9. Числа — только измеренные; изобретённое запрещено: измеримое меряется, назначаемое — решением с номером. Метка: «измерено» / «модель, на допущении …» / «догадка»; модельное решений не двигает. Найденное отбором на тех же данных (исключение «худших», подбор параметров) — при первом упоминании «найдено на этих данных»; прирост по построению — так и говорится; + проверка без заглядывания вперёд.
10. Готовность — только по счётчику на машине, в процентах, не по отчёту исполнителя.
11. Данные — как на бирже, без упрощений ради кода (SETTLED В-172): первое предложение — точная модель; упрощение — только если замер доказал, что результат не меняется.
12. Комиссия в исследованиях и бэктестах — по тарифу владельца на Bybit, на всех биржах и ногах (В-47, В-71, В-88): фьючерс мейкер 1,4 / тейкер 3,5 bps, спот мейкер 6,25 / тейкер 7,5 bps, минус 10 % возврата.
13. G-022 (коллекторы): §2 `docs/plan/G-022-collectors-plan-2026-11-12.md` (В-148 турбо, В-156 копии рядом с боевым); В-150 — правильность и полнота против биржи, не против Python и не счётчиками коллектора; `rollout.sh`; ≤ 80 % лимита IP.
14. Без бесцельного ожидания (В-147): долгие замеры и редкие эпизоды — фоновым юнитом, разбор позже; тред ждёт только нужное для следующего шага. Задачи владельца не ждут: ради незаказанного замера или окна не останавливаются; замер подстраивается под работу или пишет нагрузку рядом с числами; блок кончился — работа идёт сразу, без запаса.
15. Без многоагентных workflow и широких фан-аутов, если владелец не просил; токены не оверспендить.
16. Язык и болтовня дочерних тредов (В-151) — начало `AGENTS.md`; цитаты владельца — дословно по-русски.
17. Название треда — `<роль> · TK-<NNN> · <тема> · v<N>`: роль ∈ {коорд, исп, пров, чит, крит}; TK — номер самой задачи, не код цели G-022; тема — латиница kebab-case, одно имя на всю работу (`binance-ladder`); `v<N>` — номер попытки, у исполнителя и его проверяющего одинаковый; проверяющий — с тем же TK.
18. Проверяющего и исполнителей — только под текущую задачу владельца; нет задачи — треды не работают.
19. Передача дел — при 260 тыс. токенов контекста, клир — не позже 265 тыс. (В-161; `context_guard.py`); перед передачей и /clear всё следующее уже запущено (счёт — юнитом, исполнители — треды).
20. Перенос и переписывание: проверенное поведение как было (настройки, пороги, логика); эксперименты — только если стало хуже по замеру.
21. Страницы для владельца: макет и «да» — только для новой страницы или перекомпоновки; вкладка, колонка, настройки, подписи на существующей — сразу в бой, в её стиле.
22. Звуки и баннеры уведомлений не включать.
23. «X хуже / сломано» — гипотеза, пока не воспроизведено в равных условиях (одно окно — не вывод); работа под гипотезу не ставится. Условия (сообщ./с рынка, доля быстрых подключений, нагрузка хоста) — рядом с результатом, сравниваются равные; числа сторон — одним скриптом по сырым данным, не счётчиками сторон; эталонный тест — один в один (параллельность, по одному процессу биржи за раз), без постороннего на хосте (сборки — в Софии); сперва исключить среду, потом код.
25. Перед показом владельцу проверить самому: макет открыть, сверить с просьбой, прощёлкать каждую кнопку; о файле — по файлу, не по пересказу.
26. Бриф исполнителю — слова владельца дословно плюс нужный контекст; своих блоков, графиков, разделов не добавлять. Страница — только то, что просил: без плашек, баннеров, оговорок, один акцентный цвет.
29. Дочерний тред — `--parent-self` и сразу `--parent-notifications stuck` (`references/bb-runtime.md`): итог, сбой, нужное решение — `bb thread tell`; «жду» и промежуточные PASS / FIX координатора не будят. Координатор на тихое событие владельцу не пишет ничего, «waiting: …» тоже (22.11: «А нахуй ты весь этот мусор пишешь? Приказ же ксть»).
31. Окно счёта — все доступные данные по всем участникам; короче — только с названной причиной (дыры, смена формата), в начале отчёта и в брифе.
33. Ожидание долгой работы на srv/Софии — только `tools/srv-wait.sh` фоном (`docs/COMMANDS.md`, «Ожидание»); «ещё жду / в очереди / ещё идёт» родителю запрещены — только итог (READY / BLOCKED); опрос в цикле (ssh + sleep) запрещён.
34. Токены (В-158; `tools/token-usage.py 7`): вывод команд — через `tail`/`grep`/`head` с лимитом; логи, длинные ssh-выводы, диффы — читателю (Agent `reader`), в контекст — сводка; большой файл целиком не читать; бриф, вывод, свои шаги не пересказывать. Отчёт исполнителя — по `AGENTS.md`. Сначала доказательство бага (тест или замер на старом коде), потом правка; вслепую, пока идёт сборка/тест, не писать. Анализ, нужный второй раз, — в `tools/` тем же коммитом; разовые скрипты в ветку не класть. Простая задача — модель `simple tasks`.
35. Каждый прогон и вердикт — с просадкой ($ и % маржи) и перехаем P&L (сутки между новыми максимумами: самый длинный, средний, хвост) рядом с Σ $ и Шарпом, против базы (В-169); без них отчёт возвращается.

Слитые: 24→14, 27→9, 28→6, 30→4, 32→8; эти номера не используются.
36. Сроки (владелец 28.11: «каждый раз как спрашиваю сколько ждать или какой дл говоришь максимально близкий из возможных вариантов. запиши приказом»): на вопрос «сколько ждать / какой срок» — сразу одно число, самый близкий реалистичный срок (темп агентов, не людей), с часами по GMT+4; без вилок и запаса; помечать «оценка». Сорвался — новый срок одной строкой с причиной.
